# 병원·의원급 테마 패키지 조사·연구 계획서

- 작성일: 2026-09-20
- 문서 상태: 조사 착수 전 계획
- 목적: JW SOFT G5 병원 테마 패키지의 첫 제작 과목과 패키지 구조를 실제 수요와 실제 의원 사이트 근거로 결정한다.

## 1. 최종 결정할 사항

이번 조사의 결론은 다음 네 가지를 명확히 답해야 한다.

1. 첫 상품으로 제작할 진료과목 1순위와 차순위는 무엇인가.
2. 여러 과목이 함께 쓸 수 있는 병원 테마 공통 코어는 어디까지인가.
3. 과목별로 달라져야 하는 메뉴, 페이지, 메인 화면 블록과 예시 콘텐츠는 무엇인가.
4. 치과·한의원처럼 별도 상품군으로 분리해야 하는 분야는 무엇인가.

첫 과목은 의원 수만으로 정하지 않는다. 의료기관 규모, 환자 수요, 지역 분포, 홈페이지 구매 가능성, 실제 사이트 구조의 반복성, 기존 상품 경쟁, 의료광고·개인정보 부담을 함께 평가한다.

## 2. 조사 범위와 경계

### 주 대상

- 의원급: 단독 의원, 다인 의원, 네트워크 의원
- 병원급: 중소 병원과 특정 질환·과목 중심 병원
- 실제 구매자 가설: 병·의원 운영자, 병원 홈페이지 제작사, 그누보드5 기반 유지보수 업체

### 제외 또는 별도 참고

- 상급종합병원과 대학병원은 정보구조 참고 사례로만 본다. 규모와 기능이 상품 고객 범위와 다르므로 수요 점수에는 넣지 않는다.
- 치과의원과 한의원은 비교군으로 조사한다. 의과와 메뉴·치료 설명·운영 관행이 충분히 다르면 각각 별도 패키지로 판단한다.
- 예약·접수, 전자의무기록, 결제, 실손서류 발급 같은 업무 시스템은 테마 기본 기능으로 가정하지 않는다. 필요한 경우 외부 연결 또는 별도 플러그인 범위로 분리한다.
- 이번 단계에서는 디자인 시안, 테마 구현, 실제 의료 문구 작성, 배포를 하지 않는다.

## 4. 연구 질문

### 시장과 구매 수요

- 어느 과목에 의원·병원 수와 환자 접점이 충분히 많은가.
- 지역에 고르게 분포해 전국 판매가 가능한가.
- 검색 수요가 일시 유행인지 지속 수요인지 구분되는가.
- 자체 홈페이지를 운영하고 콘텐츠를 갱신할 필요가 큰 과목은 무엇인가.
- 그누보드5 콘텐츠몰에 유사 상품이 얼마나 있으며 품질 공백은 무엇인가.

### 실제 사이트 구조

- 과목별 1차 메뉴와 2차 메뉴는 무엇이며, 사이트 사이에서 얼마나 반복되는가.
- 방문자가 가장 먼저 찾는 진료시간, 위치, 의료진, 증상·질환, 치료, 예약 정보는 어디에 배치되는가.
- PC와 모바일의 탐색 구조 및 고정 CTA는 어떻게 다른가.
- 일반 페이지, 게시판, 문의 기능 중 그누보드5 기본 기능으로 구현 가능한 범위는 어디까지인가.
- 병원 규모보다 진료과목이 구조에 더 큰 영향을 주는가.

### 상품 패키지 구조

- 모든 과목에 공통으로 제공할 화면과 과목 전용 화면은 무엇인가.
- 같은 테마팩 안에서 과목별 완성형 구성으로 제공할 수 있는 조합은 무엇인가.
- 별도 테마로 분리할 만큼 정보구조와 시각 요구가 다른 과목은 무엇인가.
- 구매자가 텍스트·사진·메뉴를 교체하기 쉬운 구조인지, 개발자 수정이 계속 필요한 구조인지 확인한다.

## 5. 근거 자료와 사용 원칙

### 공공 통계

- [건강보험심사평가원 의원급 표시과목별 시도별 진료비 통계](https://www.data.go.kr/data/15055562/fileData.do): 표시과목별 환자 수, 청구 건수, 내원일수, 진료비와 지역 분포를 비교한다. 2025년 자료는 건강보험 급여 청구 기준이므로 비급여 시장 전체로 해석하지 않는다.
- [건강보험심사평가원 의료기관별 상세정보서비스](https://www.data.go.kr/data/15001699/openapi.do): 기관 유형, 진료과목, 전문의, 시설·장비, 지역을 확인하고 실제 사이트 표본의 의료기관 정보를 교차 검증한다.
- 건강보험심사평가원 요양기관 개설 현황: 과목별 기관 수와 최근 증감을 확인한다.

### 검색과 시장 자료

- [네이버 데이터랩 검색어 트렌드](https://datalab.naver.com/): 과목명뿐 아니라 질환·검사·시술·지역 결합어를 묶어 3년 월별 추세와 계절성을 본다. 상대 지수이므로 절대 검색량처럼 해석하지 않는다.
- [SIR 콘텐츠몰 테마 카테고리](https://sir.kr/cmall/c/10): 병원 관련 테마 수, 가격, 호환 버전, 누적 판매, 업데이트, 데모 품질과 제공 페이지를 기록한다. 누적 판매량은 현재 판매 속도나 향후 수요와 구분한다.
- 국내 웹빌더·워드프레스·홈페이지 제작사의 병원 템플릿은 메뉴와 디자인 공급 수준을 비교하는 보조 자료로만 사용한다.

### 법·운영 기준

- [의료법 제56조 의료광고의 금지 등](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1028699907)과 [의료법 시행령 제24조](https://www.law.go.kr/lsLinkCommonInfo.do?lsJoLnkSeq=1032064487)를 기준으로 치료 경험담, 효과 오인, 비교·비방, 과장 표현, 심의 대상 매체와 관련된 위험 요소를 분류한다.
- 온라인 예약·상담에서 건강정보가 수집되는 경우 개인정보·민감정보 처리 범위를 별도 검토한다.
- 실제 사이트의 문구, 사진, 도표, 전후 사진은 복사하지 않는다. 메뉴 빈도와 구조적 패턴만 근거로 사용한다.

## 6. 조사 설계

### 1차: 후보 과목 정량 선별

후보군 전체에 대해 최신 가용 연도의 다음 값을 수집한다.

- 기관 수와 최근 증감
- 환자 수, 청구 건수, 내원일수
- 수도권·비수도권 분포
- 과목·질환·시술 검색 추세
- SIR 및 타 플랫폼 유사 테마 공급량과 누적 판매 신호

정량 자료만으로 결론을 내리지 않고 상위 8개 과목을 심층 사이트 조사 대상으로 선정한다. 치과와 한의원은 점수와 무관하게 비교군 각 1개를 유지한다.

### 2차: 실제 사이트 표본 구성

- 목표: 상위 8개 과목 × 과목당 8~10개, 비교군 2개 × 각 5개, 총 74~90개 사이트
- 지역: 수도권과 비수도권을 가급적 1:1로 배분
- 규모: 단독·소규모 의원, 다인 의원·네트워크, 중소 병원을 섞어 기록
- 사이트 유형: 독립 도메인을 가진 실제 의료기관 공식 사이트
- 유효 조건: PC와 모바일에서 접근 가능하고 핵심 메뉴를 확인할 수 있어야 함
- 제외: 지도·포털 상세 페이지만 있는 기관, 블로그만 운영하는 기관, 폐업·접속 불가 사이트, 동일 네트워크의 복제 사이트 중복, 대학병원·상급종합병원

검색 상단 사이트만 모으지 않는다. 지역과 규모를 먼저 할당한 뒤 HIRA 기관 목록과 검색 결과를 교차해 표본을 정한다. 특정 과목에서 병원급 표본이 부족하면 억지로 수를 맞추지 않고 실제 분포와 결측 이유를 기록한다.

### 3차: 화면과 메뉴 전수 코딩

각 사이트에서 다음 항목을 같은 양식으로 기록한다.

- 기관명, URL, 확인일, 기관 유형, 지역, 표시과목, 주력 진료
- 1차·2차 메뉴 원문, 메뉴 깊이, 페이지 유형
- 메인 화면 섹션 순서와 CTA
- PC 헤더, 모바일 내비게이션, 모바일 하단 고정 버튼
- 의료진, 진료시간, 오시는 길, 주차, 시설·장비 표현 방식
- 증상·질환·검사·치료·수술 콘텐츠의 분류 방식
- 공지, 건강정보, 치료 사례, 후기, 상담, 예약의 사용 여부
- 비급여 안내, 개인정보처리방침, 의료광고 위험 요소
- 외부 예약, 지도, 전화, 카카오톡 등 외부 서비스 연결
- 깨진 화면, 과도한 팝업, 오래된 정보처럼 상품 개선 기회가 되는 문제

원문 메뉴는 그대로 보존하고 아래 표준 기능 코드로 한 번 더 매핑한다.

1. 병원 소개
2. 의료진 소개
3. 진료과목·센터
4. 증상·질환
5. 검사·치료·수술 프로그램
6. 장비·시설
7. 진료시간·오시는 길
8. 예약·상담·문의
9. 공지·건강정보·미디어
10. 사례·후기
11. 비급여·법정 고지·개인정보
12. 지점·외국어·기타

### 4차: 공통 구조와 과목별 구조 도출

메뉴와 화면 블록은 다음 세 단계로 구분한다.

- 공통 필수: 과목과 무관하게 다수 사이트에서 반복되고 환자 탐색에 필수인 항목
- 과목별 구성: 특정 과목에서만 반복되는 질환·검사·치료 메뉴와 메인 화면
- 선택 항목: 예약, 상담, 사례, 다국어, 지점 안내처럼 사이트 운영 방식에 따라 포함 여부가 달라지는 항목

두 과목 사이의 표준 메뉴 겹침과 페이지 구성 겹침이 각각 70% 이상이면 같은 테마팩의 과목별 완성형 구성으로 묶는 방안을 우선 검토한다. 그보다 낮거나 시각·법적 요구가 크게 다르면 별도 상품으로 분리한다. 관리자에서 과목을 생성·전환하는 기능은 연구 범위에 포함하지 않는다.

| 경쟁 공백 | 15 | 기존 G5 상품 공급 부족 8, 기존 상품의 구조·모바일·완성도 공백 7 |
| 구현·운영 부담 | 10 | 별도 시스템 의존, 개인정보, 의료광고, 지속 관리 부담이 낮을수록 높은 점수 |

모든 점수에는 근거 URL·데이터 연도·관찰일과 함께 `공식 통계`, `실제 사이트 관찰`, `시장 대리 지표`, `추론` 중 하나를 표시한다. 근거가 없는 항목은 0점 또는 미확정으로 두며 추정값으로 순위를 채우지 않는다.

## 7. 과목별 메뉴 구조 산출 방식

심층 조사 과목마다 다음 형식의 최종 사이트맵을 만든다.

```text
병원소개
├── 인사말
├── 의료진 소개
├── 시설·장비
└── 진료시간·오시는 길

진료안내
├── 과목별 질환군
├── 검사
├── 치료·수술 프로그램
└── 진료 전후 안내

이용안내
├── 예약·상담
├── 비급여 안내
└── 자주 묻는 질문

커뮤니티
├── 공지사항
└── 건강정보
```

위 예시는 조사 양식이며 최종 메뉴가 아니다. 실제 사이트 빈도, 환자 동선, 그누보드5 구현 가능성을 반영해 과목별로 다시 작성한다. 각 메뉴에는 `필수`, `권장`, `선택`, `별도 플러그인` 표시를 붙인다.

## 8. 단계별 산출물

조사 결과는 다음 파일로 남긴다.

1. `docs/research/hospital/source-register.md`: 출처, 확인일, 근거 수준
2. `docs/research/hospital/specialty-demand.csv`: 과목별 정량 지표 원자료
3. `docs/research/hospital/site-sample.csv`: 실제 사이트 표본과 기본 속성
4. `docs/research/hospital/menu-observations.csv`: 원문 메뉴와 표준 메뉴 코드
5. `docs/research/hospital/specialty-scorecard.md`: 점수, 근거, 불확실성
6. `docs/research/hospital/menu-structures.md`: 과목별 전체 메뉴 구조
7. `docs/research/hospital/package-recommendation.md`: 첫 과목, 공통 화면, 과목별 완성형 구성, 별도 상품 권고

최종 보고서에는 1순위만 제시하지 않고 탈락 과목의 이유, 근거의 한계, 다음 후보가 1순위가 되려면 달라져야 할 조건까지 기록한다.

## 9. 완료 기준

- 후보 과목 12개 이상을 같은 기준으로 정량 비교한다.
- 상위 8개 과목에서 과목당 최소 8개 유효 사이트를 분석한다.
- 모든 유효 사이트의 PC·모바일 메뉴와 핵심 CTA를 확인한다.
- 메뉴 원문과 표준화 결과를 함께 남겨 분류자의 임의 판단을 추적할 수 있게 한다.
- 시장 규모, 검색 수요, 사이트 구조, 상품 경쟁을 서로 다른 근거로 구분한다.
- 첫 과목 1개, 차순위, 공통 화면, 과목별 완성형 구성, 별도 상품군을 결정한다.
- 실제 조사 전에는 특정 과목을 최종 선정했다고 보고하지 않는다.

## 10. 조사 순서

1. 공공 통계로 후보 과목을 비교하고 상위 8개를 선정한다.
2. 실제 의료기관 사이트 표본을 확정하고 출처 대장을 만든다.
3. PC·모바일 메뉴와 메인 화면을 동일 양식으로 분석한다.
4. 과목별 공통 메뉴, 전용 메뉴, 필요한 선택 기능을 도출한다.
5. SIR 경쟁 상품과 G5 설치·운영 경계를 비교한다.
6. 점수표와 근거를 검토한 뒤 첫 제작 과목과 패키지 구조를 보고한다.
