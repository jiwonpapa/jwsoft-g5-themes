# JW-Business 모바일 메뉴 조사·개선 제안

후속 사용자 지시로 구현을 진행했습니다. [개선 결과와 실제 검증 범위](../../reports/JW-BUSINESS-MOBILE-MENU-2026-09-22.md)를 참고합니다. 아래는 구현 전 조사 기록입니다.

2026-09-22. 이번 범위는 조사·직접 화면 검토·설계 제안입니다. 테마 코드는 변경하지 않았습니다.

## 결론

모든 사이트에 최적인 모바일 메뉴는 없습니다. 현재 JW-Business 데모처럼 3단계에 여러 디자인 패턴을 모두 제공하는 구성에는 **전체 화면 + 대분류 고정 + 선택 분류의 하위 목록**을 우선 비교안으로 추천합니다. 실제 기업 사이트에서 선택한 페이지만 운영하는 경우에는 **전체 화면의 단순 2단 아코디언**이 더 간단할 수 있습니다.

이것은 아래 연구 원칙을 현재 메뉴에 적용한 설계 판단입니다. 분류 고정형이 JW-Business에서 가장 빠르다는 사용자 실험 결과는 아직 없습니다. 현재 메뉴를 판매용으로 적합하다고 판단할 근거도 없습니다.

## 직접 확인한 현재 구현

Edge의 `https://g5themes.test/`, 390×844 CSS 픽셀에서 메뉴 → 회사소개 → 기업개요를 직접 열어 확인했습니다. 실제 휴대전화·모바일 Safari·스크린리더 시험은 아닙니다.

| 관찰/실측 | 영향 또는 판정 |
| --- | --- |
| 본문 패널 폭 328px. 나머지 영역은 흐린 배경 | 여러 단계의 긴 한글 메뉴를 좁은 폭에 배치함 |
| 회사소개 아래 링크 요소 43개 | 모두 한 번에 보이는 수는 아님. 회사소개 전체 보기 1 + 7개 유형 × (대표 패턴 1 + 변형 5)의 중복 포함 수 |
| 기업개요 하나를 펼쳤을 때 패널 scrollHeight 1098px, 보이는 높이 844px | 다른 대분류와 보조 동작이 아래로 밀림 |
| 1단 행 58px/17px, 2단 제목 44px/14px, 하위 링크 37px/14px, 대표 패턴 31.5px/13px | 중요한 최종 목적지가 더 작고 약하게 보임. 44px 미만이라는 사실만으로 WCAG AA 위반이라고 하지는 않음 |
| 회사소개 ‘전체 보기’, 기업개요 ‘대표 패턴’, ‘#1 사진·소개 좌우’가 같은 주소 | ‘전체 보기’가 전체 목록을 보여준다는 기대와 다름 |
| 검색·로그아웃·문의가 동일한 큰 타일 | 기업 정보 탐색, 핵심 문의, 계정 종료의 시각적 우선순위가 구분되지 않음 |
| 열기 버튼은 아이콘만 표시 | 보이는 ‘메뉴’ 라벨 추가가 개선 후보 |

코드 확인: `src/php/partials/site-header.php`, `src/styles/theme.css`, `src/scripts/theme-controller.ts`, `src/php/lib/jw-business.lib.php`.

- 메뉴 제목/닫기 영역은 스크롤 패널 안의 일반 흐름이며 고정 처리가 없습니다. 스크롤 후 닫기 버튼 접근성을 시험해야 합니다.
- 현재 페이지 경로를 판별해 `aria-current` 또는 선택 표시를 출력하는 코드가 없습니다. 홈페이지에서 current 표시 0개인 것만으로 판단하지 않았습니다.
- 네이티브 dialog, 열기/닫기 버튼, 포커스 이동은 이미 있습니다. 전부 새 라이브러리로 바꿀 이유는 없습니다.

## 연구에서 확인한 것

### 1. 메뉴를 숨기는 비용은 있지만, 햄버거를 무조건 없애라는 뜻은 아님

NN/g의 2016년 연구는 179명·6개 사이트를 조사했습니다. 모바일에서는 숨김 메뉴와 일부 노출 메뉴를 비교했고, 메뉴 사용 비율은 각각 57%, 86%였습니다. 모바일 완전 노출 조건은 시험하지 않았습니다. 이를 현재 테마의 전환율 향상 수치나 2026년의 보편적 비율로 사용할 수는 없습니다.

적용: ‘메뉴’ 텍스트를 표시하고, 문의 같은 주요 목적지는 메뉴를 열기 전에도 접근할 수 있게 합니다. 햄버거 아이콘만 바꿔 같은 효과가 난다는 주장은 하지 않습니다. [NN/g: Hamburger Menus and Hidden Navigation Hurt UX Metrics](https://www.nngroup.com/articles/hamburger-menus/)

### 2. 아코디언은 하위 항목이 적을 때 유리함

NN/g는 적은 하위 항목에는 아코디언을, 항목이 많아지면 섹션 메뉴·분류 안내 페이지를 검토하도록 설명합니다. 문서의 ‘6개 미만, 6~15개, 15개 초과’는 선택을 돕는 경험적 지침이며 절대 규칙이 아닙니다. 계층마다 화면 전체가 바뀌는 순차 메뉴는 위치 상실과 브라우저 뒤로가기 혼동을 일으킬 수 있다고 지적합니다.

적용: 3단계 접기 목록을 그대로 길게 늘이지 않습니다. 대분류를 항상 남겨 회사소개에서 사업분야로 되돌아가려는 사람의 위치 파악을 돕습니다. 7개 회사소개 유형과 각 5개 패턴을 합쳐 단순히 ‘35개니까 금지’라고 판단하지는 않습니다. [NN/g: Mobile Subnavigation, 2017](https://www.nngroup.com/articles/mobile-subnavigation/)

### 3. 펼치기와 목적지 이동은 구별해야 함

Baymard는 모바일의 상위 분류 탭이 펼치기인지 이동인지 모호해지는 문제와 실제 전체 목록으로 가는 링크의 필요성을 설명합니다. 이는 쇼핑몰 연구이며 기업 테마에 같은 수치 효과가 난다는 근거는 아닙니다.

적용: 펼치기는 버튼, 페이지 이동은 링크로 구분합니다. 실제 전체 목록이 있을 때만 ‘전체 보기’를 씁니다. 현재처럼 대표 페이지 #1을 전체 보기로 이름 붙이지 않습니다. [Baymard: Have a “View All” Option in the Mobile Main Navigation at Each Level](https://baymard.com/research-articles/mobile-main-nav-view-all)

### 4. 터치·접근성은 취향과 구별해야 함

- WCAG 2.2 AA 2.5.8의 기본 최소는 24×24 CSS px이며 간격 등 예외가 있습니다. 44×44는 별도의 강화 기준(AAA 2.5.5)입니다. 이 테마는 중요한 터치 영역에 44px 이상, 일반 메뉴 행은 48~56px를 설계 목표로 삼는 것이 타당합니다. 후자는 프로젝트 제안값입니다. [W3C 최소 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html), [강화 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced)
- 일반 사이트 탐색에는 `nav`, 목록, 링크, 펼치기 버튼을 사용합니다. 데스크톱 앱 같은 키보드 계약이 필요한 `role=menu`를 이름만 보고 붙이지 않습니다. [W3C Disclosure Navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/)
- 모달 메뉴에서는 포커스 진입·내부 이동·Escape 닫기·호출 버튼으로 복귀를 확인합니다. [W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)

### 5. 하단 탭바는 다단계 메뉴의 대체품이 아님

Android 공식 지침의 하단 navigation bar는 같은 계층의 3~5개 목적지를 위한 것입니다. 앱 지침을 기업 웹사이트에 그대로 적용할 수는 없습니다. 현재 5개 대분류가 있다는 이유만으로 하단 탭바가 최적이라고 결론낼 수 없고, 75개 패턴 탐색 문제도 남습니다. [Android: Layouts and navigation patterns](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)

## 후보 비교 — 프로젝트에 대한 판단

| 방식 | 장점 | 비용/문제 | 현재 판정 |
| --- | --- | --- | --- |
| 좁은 드로어 + 중첩 아코디언 | 익숙함, 단순 구현 | 펼칠수록 길어지고 상위 선택지가 밀림 | 현재 구성에는 부적합 |
| 전체 화면 + 2단 아코디언 | 넓은 링크, 전체 분류를 같은 흐름에서 탐색 | 패턴까지 3단을 넣으면 기존 문제 반복 | 실제 기업용의 적은 항목에 적합 |
| 전체 화면 + 대분류 고정 + 하위 목록 | 대분류 간 이동과 현재 위치가 계속 보임 | 좌우 분할 시 본문 폭 감소. 긴 한글과 확대 시험 필요 | 패턴을 모두 제공하는 현 데모의 우선 비교안 |
| 단계마다 화면을 교체하는 메뉴 | 각 목록을 넓게 사용 | 상위 위치 상실, 뒤로가기 의미 혼동 | 우선 채택하지 않음 |
| 하단 탭바 | 주요 목적지 지속 노출 | 화면 점유, 하위 패턴 문제 미해결 | 핵심 메뉴의 기본 대체안으로는 보류 |

## 추천 구성

현재 데모의 여러 패턴을 삭제하거나 접근 불가능하게 만들지 않습니다. ‘일반 기업 방문자’와 ‘구매 전 패턴을 비교하는 사람’의 목적이 다름을 반영합니다.

```text
전체 메뉴                              닫기
──────────────────────────────────────────
회사소개  │ 회사소개
사업분야  │ 기업개요                    펼치기
프로젝트  │   #1 사진·소개 좌우
인재채용  │   #2 기업 정보표 중심
고객지원  │   #3 넓은 사진·소개
          │   #4 실적·기업 정보 조합
          │   #5 편집형 장문 소개
          │ 대표 인사말                 펼치기
          │ 비전·가치                   펼치기
          │ …
──────────────────────────────────────────
검색 · 내 정보/로그인 · 화면 모드    문의하기
```

이것은 동작 설명용 도식이며 승인된 시안은 아닙니다.

- 바깥 패널은 모바일 전체 폭과 `100dvh`, safe area 반영. 제목/닫기는 항상 접근 가능하게 유지합니다.
- 대분류는 5개를 고정 노출하고 선택 배경·글자 굵기·선택 상태를 함께 표시합니다. 마우스 호버에 의존하지 않습니다.
- 오른쪽에서 유형별 펼침은 한 단계만 둡니다. 동일 유형의 5개 패턴은 실제 링크이며 #1을 ‘대표 패턴’이라는 이름으로 중복하지 않습니다.
- 메뉴가 많은 데모에서는 유형 하나를 열었을 때 같은 영역의 다른 유형을 닫는 방식을 비교합니다. 자동 스크롤로 사용자의 위치를 갑자기 바꾸지 않습니다.
- 현재 페이지 소속 분류·유형과 정확한 링크를 표시하되, 다른 대분류로 가는 길을 숨기지 않습니다.
- 일반 기업용에서는 선택한 페이지를 바로 링크합니다. 패턴 5종을 운영 메뉴에 강제하지 않습니다. 데모의 전체 패턴 접근은 유지합니다.
- 검색·계정·화면 모드는 보조 기능으로, 문의는 주 동작으로 구분합니다. 로그아웃을 문의와 동급의 큰 타일로 만들지 않습니다.
- 글자는 기본 16px를 출발점으로 잡고, 긴 이름은 2줄을 허용합니다. 행 높이 48~56px, 보조 버튼 44px 이상. 320px에서 좌우 분할의 공간 비용을 반드시 확인합니다.
- 모션은 메뉴 등장/전환에만 짧게 사용하고 reduced motion을 존중합니다. 정확한 지속시간은 프로토타입 검토값이며 연구가 보장한 숫자가 아닙니다.
- 추가 메뉴 플러그인, jQuery, 관리자 설정 시스템은 필요하지 않습니다. 기존 navigation 데이터, native dialog, 테마 CSS/TypeScript 범위에서 구현 가능합니다.

## 구현 전에 비교할 과제와 통과 기준

추천 배치를 곧바로 ‘최적’이라고 확정하지 말고 같은 콘텐츠로 현재안과 비교합니다.

1. 처음 방문: 기업개요 #2 찾기.
2. 깊은 위치에서 이동: 기업개요 #4에서 사업 상세 #3 찾기.
3. 빠른 업무: 문의하기, 공지사항 찾기.
4. 자기 위치 확인: 직접 링크로 연혁 #3에 들어온 뒤 메뉴에서 현재 위치 확인.
5. 복귀: 메뉴를 열고 스크롤한 다음 닫아 원래 본문 위치로 돌아오기.

측정: 과제 성공, 잘못 누른 횟수, 탭 수, 스크롤 거리, 소요시간, 주관적 어려움. 같은 사람에게 두 안을 비교하면 순서를 교차해 학습 효과를 줄입니다. 소수 탐색 시험 결과를 전체 사용자 통계로 일반화하지 않습니다.

기술 확인: 320/360/390/768px, 긴 한국어·200% 확대, 라이트/다크, 비회원/회원, 강제 G5 모바일 경로, 터치 Safari/Chrome, 키보드·VoiceOver/TalkBack, Escape와 기기 뒤로가기, 배경 스크롤·스크롤 경계, 회전/리사이즈, safe area. 기기 뒤로가기 정책은 메뉴 닫기와 실제 이전 페이지 이동을 구분해 시험하며 불필요한 방문 기록을 쌓지 않습니다.

현재는 직접 브라우저 관찰과 문헌 검토까지 완료했습니다. 비교 프로토타입, 실제 사용자 시험, 실기기 접근성 검증, 메뉴 코드 개선은 아직 하지 않았습니다.
