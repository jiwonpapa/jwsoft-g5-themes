# 해외 상위 WordPress 테마의 페이지 구성과 JW-Business 적용 방향

- 조사일: 2026-09-21
- 대상: ThemeForest Business 누적 판매순 상위 4개 및 Creative 분야의 대형 판매 상품 2개
- 상태: 조사·기획. 같은 하위 페이지 유형마다 4~5종 제공은 사용자 요구사항이며, 구체 레이아웃은 제안
- 구현·시안 제작·설치·배포: 이번 조사에 포함하지 않음

후속 결정: [출시 구현 범위](../../plans/JW-BUSINESS-1.0-IMPLEMENTATION-SCOPE.md)에서 모든 페이지 유형을 5종으로 통일하고 총 75개 레이아웃을 확정했다. 아래의 4~5종·28~35종은 조사 당시 요구 범위와 계산 예시이며, 현재 출시 수량은 확정 범위 문서를 따른다.

## 1. 결론

**JW-Business는 같은 하위 페이지 유형마다 완성 레이아웃을 4~5종씩 고를 수 있는 상품으로 기획한다.** 기업개요·인사말·연혁 등 서로 다른 하위 메뉴를 합쳐 '회사소개 5종'으로 세지 않는다. 기업개요 1~5, 인사말 1~5, 연혁 1~5가 각각 필요하다. 기존의 메인 1종·일반 페이지 총 10개 및 상위 메뉴 6분류 30종 제안은 이 요구를 잘못 해석한 집계이므로 폐기한다.

해외 상위 상품에서 확인된 공통 원리는 완성 사이트와 페이지의 선택권, 반복 사용하는 요소·섹션, 이를 찾아 적용하는 카탈로그다. 특히 The7은 한 데모 안에서 회사소개 4종·연락처 7종·Q&A 3종을 제공해 사용자 요구와 직접 대응한다.

다만 이번 해외 조사로 모든 상품의 기업개요·인사말·연혁·조직도 각각이 5종씩 제공된다고 확인한 것은 아니다. **하위 페이지마다 4~5종이라는 기준은 사용자 요구와 JW의 상품 전략이며, 시장 전체의 일률적인 수량 규칙은 아니다.** 여러 페이지 제공이 높은 판매량의 원인이라고 단정할 자료도 없다.

## 4. 같은 분류의 페이지는 무엇이 다른가

The7 About 1·4는 Edge에서 메뉴를 펼쳐 이동하고 전체 화면도 육안 비교했다. 1번의 사진형 상단·수치·후기와 4번의 간결한 제목·큰 교차 이미지 구성이 다르다. 4번 일부 하단 이미지는 캡처 시 지연 로딩 상태였으므로 자산 로딩 품질 검증으로 취급하지 않는다.

이들 기존 데모는 **상품 구성 방식**의 근거다. 특히 The7 Main·Bridge Original의 시각 스타일을 최신 디자인 표준으로 채택하지 않는다.

### 4.2 메인 — 동일한 기업 정보를 다른 순서로 제시

[Avada Business Default](https://avada.website/business/)는 사업·서비스와 미션·비전·전략, 파트너·전문가·역량·뉴스를 조합한다. [Alternate](https://avada.website/business/business-home-alternate-2/)는 파트너를 앞에 두고 기업 강점·서비스·프로젝트·후기·문의·뉴스로 이어진다. 같은 데모에서도 정보 순서와 행동 유도가 다르다.

[Bridge Home 1](https://demo.qodeinteractive.com/bridge/)과 [Home 2](https://demo.qodeinteractive.com/bridge/home-2/)도 기업 소개·수치·실적을 조합하는 방식과 소개·서비스·문의의 진입점 배치가 다르다. 메인 변형을 별도 테마처럼 코드를 복제할 이유는 없다.

해외 Contact 여러 종이 곧 국내식 고객센터 여러 종이라는 뜻은 아니다. JW에서는 **공지·FAQ·자료·1:1 문의를 안내하는 고객지원 페이지**와 **주소·전화·운영시간·길찾기를 안내하는 연락처 페이지**를 별도 분류한다.

## 5. 상위 상품에서 참고할 공통 구조

1. **완성된 페이지를 먼저 고를 수 있다.** 빈 캔버스에서 시작하도록 요구하지 않는다.
2. **페이지 아래에 재사용 단위가 있다.** 같은 소개·수치·팀·후기·연락 블록을 다른 페이지에서도 활용한다.
3. **사진 교체보다 정보 구성이 선택 기준이 된다.** 팀이 중요한 회사, 실적이 중요한 회사, 설명이 많은 회사가 고를 수 있어야 한다.
4. **데모·페이지·섹션을 찾는 탐색 구조가 중요하다.** 페이지가 많아도 필요한 것을 찾을 수 없으면 편집 부담이 생긴다.

재사용 방식의 공식 근거:

- [The7 Single Page Import](https://guide.the7.io/elementor/user-guide/the7-dashboard/the7/): 특정 페이지를 가져오며 현재 사이트 스타일을 상속. 같은 빌더를 선택하도록 안내.
- [Salient Studio](https://themenectar.com/docs/salient/salient-studio/): 섹션 삽입 후 일반 행·열·요소로 편집·재배치. 원본 라이브러리와 계속 동기화되는 구조는 아님.
- [Betheme BeBuilder](https://support.muffingroup.com/documentation/bebuilder/how-to-use/): Section·Wrap·Item 단위와 복사·붙여넣기.
- [Enfold Import Demos](https://kriesi.at/documentation/enfold/import-demos/): 다른 데모의 페이지를 가져오거나 요소 코드를 복사하는 절차 및 설정·미디어 관련 주의사항.

빌더 의존성까지 채택하는 제안은 아니다. JW는 기존의 완성 HTML/PHP 페이지·섹션·매뉴얼 배포 방식으로 같은 선택권을 제공한다.

## 6. JW-Business 페이지 구성 제안

### 6.1 제공 단위 — 상위 메뉴 아래 각각의 하위 페이지 × 4~5패턴

`상위 메뉴 → 하위 페이지 유형 → 레이아웃 01~05`를 상품 카탈로그 구조로 삼는다. 예를 들어 `회사소개 → 연혁 → 연혁 03`이다. 이는 구매자용 카탈로그 분류이며 실제 사이트에 3단 메뉴를 추가하라는 뜻은 아니다.

| 상위 메뉴·영역 | 각각 4~5종을 갖춰야 하는 페이지 유형 |
| --- | --- |
| 메인 | 메인 페이지 자체의 레이아웃 4~5종 |
| 회사소개 | 기업개요, 대표 인사말, 비전·가치, 연혁, 조직도, 인증·수상, 오시는 길 **각각** 4~5종 |
| 사업영역 | 사업 목록, 사업 상세, 프로세스 **각각** 4~5종 |
| 인재채용 | 인재상, 복리후생 **각각** 4~5종 |
| 고객지원 | 고객센터 안내 페이지 자체의 레이아웃 4~5종. 실제 G5 기능 화면과 구분 |
| 연락처 | 연락처 안내 페이지 자체의 레이아웃 4~5종. 오시는 길과 동일한 제공물이면 중복 집계하지 않음 |

사업 상세에 사업 A·B 데이터를 넣은 결과는 레이아웃 두 종류가 아니다. 반대로 기업개요와 인사말은 서로 다른 페이지 유형이므로 둘을 합쳐 회사소개 2종으로 세지 않는다. 같은 페이지가 여러 메뉴에서 연결돼도 제공 수량은 한 번만 센다.

회사소개 하위 7개 유형을 기준으로 하면 **회사소개 영역만 28~35개 완성 레이아웃**이 된다. 이는 요구사항의 집계 예시이며 상품 전체 수량을 임의로 확정한 것은 아니다. 채용공고·공지·게시판·FAQ·검색·1:1 문의 등의 G5 기능 화면은 기존 별도 사양을 따르며, 이번 일반 페이지 요구를 근거로 모든 기능 스킨을 5종씩 늘리지 않는다.

| 조직도 | 수직 계층도 | 수평 계층도 | 부서별 들여쓰기 목록 | 대표 영역·하위 부서 묶음 | 사업부별 계층 열 |
| 인증·수상 | 증서 격자 | 증서·설명 가로 목록 | 분야별 묶음 | 큰 증서·상세 설명 | 간결한 인증 목록 |
| 오시는 길 | 지도 상단·안내 하단 | 지도·주소 좌우 | 교통수단 안내 우선 | 방문 사진·주차 안내 | 지점별 위치 묶음 |

각 패턴은 해당 페이지의 목적을 유지한다. 연혁 5종 모두 같은 연혁 데이터를 담을 수 있어야 하고, 조직도 5종 모두 상하 관계를 전달해야 한다. 다른 목적의 페이지로 대체해 패턴 수를 채우지 않는다.

### 6.3 변형으로 인정하는 기준

- 같은 회사 정보로 비교해도 첫 화면·핵심 정보 순서·섹션 구성·이미지와 글의 비중에 설명 가능한 차이가 있어야 한다.
- 색상·사진·아이콘만 바꾼 복제는 별도 페이지 유형으로 세지 않는다.
- `회사소개 > 연혁 03 — 연도별 표형`처럼 하위 페이지명·번호·레이아웃 특성을 함께 표기한다.
- 자료가 적은 회사에도 쓸 수 있는 간결한 조합을 포함하고, 불필요한 실적·팀·후기를 채우도록 강요하지 않는다.
- 각 조합은 완성된 예시 문구·이미지·모바일 배치·라이트/다크 상태까지 포함해야 한다.

### 6.4 일관성과 재사용

공통 색상·서체·버튼·아이콘·간격·G5 스킨은 하나의 기준을 따른다. 그 위에서 페이지별 구성과 시각적 리듬을 다르게 한다. 5개 페이지마다 토큰·JS·문의 처리 코드를 별도 복제하지 않는다.

개발 원본은 섹션과 페이지 조합 recipe로 관리하고, 고객에게는 사용할 수 있는 완성 파일을 제공한다. HTML 복사형은 G5 내용관리 저장 왕복 검증을 전제로 하며, 최신글·로그인·FAQ 등 서버 데이터가 필요하면 PHP 조합형을 사용한다. PHP를 내용관리 HTML에 붙여넣게 하지 않는다.

## 7. CS를 늘리지 않는 배포·매뉴얼

| 구매자 작업 | 제공할 수단 |
| --- | --- |
| 적합한 페이지 선택 | 상위 메뉴 아래 하위 페이지마다 01~05 미리보기와 추천 용도 |
| 필요한 준비물 확인 | 사진 개수·비율, 제목·문구·실적·주소 등의 입력 자료표 |
| 그대로 사용 | 완성 페이지 파일 또는 검증된 HTML과 적용 절차 |
| 일부만 교체 | 사용 섹션 목록·시작/끝 주석·다른 섹션과 교체하는 예시 |
| 메뉴 연결 | 실제 파일/내용관리 주소와 G5 메뉴 설정 위치 |
| 업데이트 | 원본·수정본 구분, 변경 부분과 복원 절차 |

고객센터가 5종이어도 문의 저장·권한·CAPTCHA·첨부·메일 처리는 기존 G5 흐름을 사용한다. 새 문의 폼 생성기, 티켓 시스템, 통합 검색 색인, CRM, 지도 API 자동 설정을 추가하지 않는다. 실시간 FAQ·공지 목록의 데이터 연결 가능 여부는 구현 전 G5 계약에서 확인한다.

제공 원본과 공식 복사 절차의 결함은 지원하고, 고객별 페이지 조합·문구·디자인 편집 대행은 기존 CS 정책대로 매뉴얼로 안내한다. 페이지 수 증가에 따른 검수 비용 자체가 없어지는 것은 아니다.

## 8. 검증 계획과 다음 설계

- 모든 하위 페이지의 각 패턴에서 PC·모바일 × 라이트·다크를 확인한다. 검사 수는 중복 없는 전체 레이아웃 수 × 4로 산정하고, 잘못 집계했던 30종·120개 검사 기준은 사용하지 않는다. 검사 실행은 아직 전이다.
- 폼·권한·업로드처럼 동일한 G5 기능의 상세 시험은 공통 구현을 기준으로 수행하되, 각 페이지의 진입 링크·데이터 연결·빈 상태는 각각 확인한다.
- 같은 섹션 여러 번 삽입, 순서 변경, 긴 문구·이미지 없음, 모션 감소를 확인한다.
- 페이지별 제목·설명·메타는 해당 내용 기준으로 작성한다. 페이지 유형 수를 이유로 SEO 관리 기능을 확대하지 않는다.
- 전체 하위 페이지 목록 → 각 하위 페이지의 4~5개 레이아웃 구성안 → 같은 하위 페이지의 패턴 간 시안 비교 → 승인된 토큰·섹션 설계 순서로 진행한다. 실제 구현은 별도 지시 뒤 시작한다.

## 9. 증거 한계

공식 판매 목록·개발사 문서·공식 데모의 본문과 메뉴를 중심으로 조사했다. The7 About 1·4는 Edge에서 렌더링 화면까지 확인했다. 모든 데모의 모바일·폼 제출·접근성·설치 동작을 시험한 것은 아니다.

Enfold 기본 데모는 웹 도구에서 접근 제한이 있어 공식 데모 저장소의 구형 원본 구성을 보조 근거로 사용했다. 공식 최신 Studio 페이지의 검색 수집 본문은 최신 화면을 직접 본 증거로 취급하지 않았다. 상품마다 마케팅 수량의 집계 시점과 단위가 다르므로 수량만으로 품질을 비교하지 않는다.
