# JW SOFT 테마 온라인 매뉴얼 운영 표준 v1.0

- 문서 상태: 구현 전 운영 기준 확정
- 기준일: 2026-09-20
- 적용 범위: JW SOFT G5·영카트5 유료 테마의 설치·업데이트·수정 안내
- 제외 범위: 개별 사이트 제작 교육, 서버 운영 대행, 별도 플러그인 설명서

## 1. 결론

테마 상품의 추가 기능을 늘리는 대신 **설치·수정·자가진단을 정확히 끝낼 수 있는 온라인 매뉴얼**에 투자합니다. 같은 질문을 사람에게 반복하게 만드는 문서 누락은 제품 결함으로 관리하고, 고객별 변경 대행은 테마 CS에서 분리합니다.

매뉴얼의 목표는 세 가지입니다.

1. 구매자가 지원 문의 없이 설치와 기본 수정을 완료한다.
2. 문의가 들어오면 한 개의 정확한 문서 URL로 먼저 해결한다.
3. 실제 테마 결함만 재현 정보와 함께 접수되게 한다.

## 2. 제품과 문서의 경계

| 테마 상품에 포함 | 온라인 매뉴얼이 설명 | 테마 CS에서 제외 |
| --- | --- | --- |
| 설치 가능한 테마 ZIP | 설치·업데이트·롤백 절차 | 원격 설치·이전 대행 |
| 명시한 화면과 시각 효과 | 로고·색상·폰트·메뉴·이미지 변경 위치 | 고객별 디자인·PHP 수정 |
| 지원 버전에서의 호환성 | 캐시 초기화와 자가진단 | 서버·도메인·SSL·메일 설정 |
| 공식 업데이트 | 변경 이력과 영향 범위 | 외부 플러그인 충돌 분석 |
| 테마 코드 보안 수정 | 안전한 문의 접수법 | 해킹 복구와 서버 보안 운영 |

`jw-editor for G5`, 예약, 업로더, 외부 연동은 별도 상품·별도 URL·별도 지원 정책으로 운영합니다. 테마 설치에 필수가 아닌 기능을 매뉴얼에서 권장 설치하지 않습니다.

## 3. 배포 방식

### 3.1 정적 문서 사이트

온라인 매뉴얼은 DB·회원가입·실시간 상담이 없는 정적 사이트로 배포합니다. 고객 브라우저에는 문서 HTML/CSS/검색 index만 제공하며 테마 제품 소스와 독립적으로 갱신합니다.

| 항목 | 초기 고정 기준 | 용도 |
| --- | --- | --- |
| package manager | Bun 1.4.2 | 저장소 공통 lockfile·명령 사용 |
| framework | Astro 7.3.3 | 정적 HTML 생성 |
| docs UI | Starlight 0.42.2 | 문서 navigation·접근성·모바일 화면 |
| 검색 | Pagefind 1.5.2 | 별도 검색 서버 없는 전체 문서 검색 |

Starlight는 정적 빌드에서 Pagefind 전체 검색을 기본 제공하므로 검색 서버와 계정 기능을 운영할 필요가 없습니다. 버전 관리는 외부 community plugin을 추가하지 않고 디렉터리와 URL로 해결합니다. 실제 구현 때 exact version과 `bun.lock`을 고정하고 `bun audit`과 정적 빌드를 통과시킵니다.

권장 저장 위치는 `apps/manual/`이며, 테마 소스와 같은 저장소에서 문서 링크 유효성과 상품 버전을 함께 검사합니다. 판매 ZIP에는 사이트 generator를 넣지 않습니다.

### 3.2 URL 규칙

```text
/themes/<theme-slug>/<major.minor>/quick-start/
/themes/<theme-slug>/<major.minor>/install/
/themes/<theme-slug>/<major.minor>/update/
/themes/<theme-slug>/<major.minor>/customize/<topic>/
/themes/<theme-slug>/<major.minor>/troubleshooting/<symptom>/
/themes/<theme-slug>/latest/  -> 현재 지원 minor 안내
```

- 고객이 보는 URL에는 상품 slug와 `major.minor`를 넣습니다.
- 문서 상단에는 적용 가능한 정확한 테마 patch 범위와 수정일을 표시합니다.
- 동작이 바뀐 minor 문서는 덮어쓰지 않고 새 경로로 만듭니다.
- 과거 지원 문서는 해당 버전 지원 종료 후 90일까지 유지한 뒤 archive 표시합니다.
- 판매 ZIP의 `README.html`은 ZIP 자체 버전과 일치하는 URL로 연결합니다.

## 4. 테마마다 반드시 제공할 문서

| 순서 | 문서 | 완료 기준 |
| --- | --- | --- |
| 1 | 5분 시작 | 지원 환경 확인부터 테마 활성화와 첫 화면 확인까지 한 흐름 |
| 2 | 설치 | 신규·기존 사이트를 구분하고 백업·권한·복사 위치·검증·원복 포함 |
| 3 | 초기 설정 | G5 관리자 메뉴와 테마 화면의 연결 관계 설명 |
| 4 | 메뉴 구조 | 1·2·3차 메뉴, 모바일 메뉴, 현재 위치 규칙과 제한 |
| 5 | 변경 위치표 | 로고·색상·폰트·대표 이미지·문구별 관리자 화면 또는 파일 경로 |
| 6 | 페이지·게시판 연결 | 스킨 선택, 게시판 table, content page 연결과 예시 |
| 7 | 업데이트 | 영향 파일, 보존 파일, 백업, 적용, 검증, 롤백 |
| 8 | 문제 해결 | 증상별 원인 분기와 사용자가 안전하게 할 수 있는 확인 |
| 9 | 지원 범위 | 지원/제외 사례와 문의에 필요한 정보 |
| 10 | 변경 이력 | 추가·변경·수정·보안 영향과 필요한 고객 조치 |
| 11 | 로컬 빌드 환경 | 개발 키트의 Bun 버전·setup·doctor·build·AI 헌법·원복·지원 경계 |

영카트를 지원하는 테마는 쇼핑몰 활성화, 상품·분류 화면 연결, 주문 화면 확인 문서를 추가합니다. 의료 테마처럼 법적 표현 위험이 있는 업종은 샘플 문구가 법률·심의 자문이 아니라는 점과 구매자가 실제 내용을 검토할 책임을 명시합니다.

## 5. 변경 위치표 형식

자주 받는 “어디서 바꾸나요?” 문의는 아래 표 한 행으로 끝낼 수 있어야 합니다.

| 바꿀 항목 | 변경 위치 | 입력 규격 | 적용 확인 | 업데이트 보존 | 문서 |
| --- | --- | --- | --- | --- | --- |
| 로고 | `<ADMIN_OR_PATH>` | SVG/PNG, 권장 크기 | PC·모바일 header | `<YES_OR_BACKUP>` | `<ARTICLE_URL>` |
| 대표 색상 | `<TOKEN_OR_PATH>` | HEX와 대비 조건 | button·link·focus | `<YES_OR_BACKUP>` | `<ARTICLE_URL>` |
| 메뉴 | `<G5_ADMIN_PATH>` | 최대 depth와 글자 수 | desktop·mobile | 예 | `<ARTICLE_URL>` |
| 히어로 이미지 | `<ADMIN_OR_PATH>` | 비율·최대 용량 | 390px·1440px | `<YES_OR_BACKUP>` | `<ARTICLE_URL>` |

테마 구현은 이 표에 적을 수 있는 공식 변경 지점을 제공해야 합니다. 고객이 vendor·minified 파일을 직접 고치게 하는 절차는 작성하지 않습니다.

## 6. 문서 한 페이지의 표준 형식

각 절차 문서는 다음 순서로 씁니다.

1. **적용 대상**: 상품, 테마 버전, G5/PHP 조건
2. **완료 모습**: 사용자가 얻는 결과 한 문장과 실제 화면
3. **시작 전**: 백업과 필요한 권한, 되돌릴 파일
4. **절차**: 한 단계에 한 행동, 실제 관리자 메뉴명과 정확한 경로
5. **확인**: PC·모바일에서 성공을 판정하는 방법
6. **원복**: 실패했을 때 안전하게 되돌리는 방법
7. **막힐 때**: 증상별 문서 링크와 문의 시 제출할 정보
8. **변경 기록**: 문서 수정일과 적용 patch 범위

화면 캡처는 실제 지원 G5에서 생성하고 비밀번호·API key·환자·회원 정보를 포함하지 않습니다. 버전이 다른 관리자 화면을 하나의 절차에 섞지 않습니다.

## 7. 문제 해결 문서 원칙

- 오류 메시지 그대로 검색되게 제목과 본문에 기록합니다.
- 하나의 문서에는 하나의 증상과 판정 흐름만 둡니다.
- “캐시를 지워 보세요” 같은 무조건 조치를 쓰지 않고 어떤 캐시를 왜 지우는지 적습니다.
- DB 직접 수정, 광범위한 권한 완화, 코어 덮어쓰기, 출처 불명 plugin 설치를 해결책으로 제시하지 않습니다.
- 지원 범위를 벗어나면 진단을 계속 확장하지 않고 어느 범위인지 명시합니다.
- 문서대로 원본 테마에서 재현되면 문의 양식으로 연결합니다.

## 8. CS 처리 흐름

1. 주문번호, 상품·테마·G5·PHP 버전과 증상을 받습니다.
2. 사용법 문의면 정확한 버전의 매뉴얼 URL 한 개를 답합니다.
3. 문서가 없거나 틀렸으면 문서 결함으로 등록하고 먼저 수정합니다.
4. 문서대로 원본 테마에서 재현되면 테마 결함으로 접수합니다.
5. 고객 수정, 서버, 외부 plugin 문제면 지원 경계를 안내하고 종료합니다.

문의 답변에서 새 설치법을 즉석 작성하지 않습니다. 유효한 해결법이면 매뉴얼에 먼저 반영해 모든 구매자에게 같은 답을 제공합니다.

## 9. 문서 릴리스 게이트

테마 판매·업데이트 전에 다음을 모두 확인합니다.

- 테마 ZIP 버전과 매뉴얼 적용 버전 일치
- 신규 설치와 업데이트 절차를 깨끗한 G5에서 실제 수행
- 모든 관리자 메뉴명·파일 경로·명령 복사 실행 확인
- PC·모바일 캡처가 현재 테마와 일치
- 내부 링크·anchor·외부 링크와 `latest` alias 검사
- 검색어 `설치`, `로고`, `색상`, `메뉴`, `업데이트`, 대표 오류 메시지로 결과 확인
- 404 page에서 검색과 상품 목차로 복귀 가능
- 지원 범위와 문의 양식 링크 확인
- 문서 없는 기능은 판매 기능 목록에서 제외

자동 링크 검사만으로 절차를 검증했다고 보고하지 않습니다. 실제 G5에서 문서만 보고 성공하는지 확인해야 합니다.

## 10. 운영 지표

개인정보를 수집하는 복잡한 분석 기능은 넣지 않습니다. 월별로 다음 수치만 관리합니다.

| 지표 | 목적 |
| --- | --- |
| 판매 100건당 테마 문의 수 | CS 총량 변화 확인 |
| 매뉴얼 URL 답변으로 종결된 비율 | 문서의 해결력 확인 |
| 같은 주제로 반복된 문의 수 | 보완할 문서 우선순위 결정 |
| 검색 결과가 없던 상위 검색어 | 제목·용어·누락 문서 개선 |
| 설치/업데이트 문서 오류 건수 | 출시 게이트 품질 확인 |
| 실제 테마 결함으로 판정된 비율 | 사용법 문의와 제품 오류 분리 |

목표 수치는 첫 상품 출시 후 90일 기준선을 만든 뒤 정합니다. 근거 없이 사전 목표치를 만들지 않습니다.
