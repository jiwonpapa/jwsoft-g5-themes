# JW-Business 1.0 출시 구현 범위

- 확정일: 2026-09-21
- 상태: 구현 범위 확정. 2026-09-22 독립 홈·일반 페이지 구조와 강제 검사 반영, 개별 화면 완성도 검증 진행 중
- 대상: `themes/business/jw_business`, 설치 경로 `theme/jw_business`
- 현재 작업: 공식 basic 기반 테마, 완성형 홈 5개, 웹루트 일반 페이지 70개 구조 반영. 다음 단계는 미완성 레이아웃의 개별 디자인과 실제 G5 화면 검증
- 우선순위: 기존 연구서의 후보·초안과 수량이 다르면 이 문서의 출시 범위를 적용

## 1. 출시 산출물

| 구분 | 확정 범위 |

75개는 디자인 레이아웃 수다. 같은 레이아웃의 PC·모바일, 라이트·다크, HTML·PHP 형식과 데모 데이터 교체를 별도 상품 수량으로 세지 않는다. G5 기능 화면과 정책 페이지는 별도 필수 범위이며 75개에 포함하지 않는다.

기존의 4~5종 요구에서 **모든 유형을 5종으로 통일**한다. 75개와 필수 기능·매뉴얼이 모두 준비되어야 1.0 출시 완료다. 개발 단계를 나누더라도 나머지 약속을 유료 업데이트로 미루지 않는다.

- 고객센터 안내는 G5 FAQ·공지·자료실·1:1 문의로 연결하는 페이지다. 5개의 별도 상담 시스템을 만들지 않는다.
- 일반 페이지의 사진·수치·문구는 교체 가능해야 하며, 자료가 적은 회사도 사용할 간결한 패턴을 포함한다.
- 일반 페이지 ID 뒤에 `-1`~`-5`를 붙여 `/pages/company-overview-1.php`처럼 미리보기·독립 PHP 파일·매뉴얼·검증 기록을 연결한다. 메인 5종은 테마의 `index_1.php`~`index_5.php`다.
- 75개 페이지를 실제 운영 메뉴에 동시에 등록하도록 강요하지 않는다. 구매자는 유형별로 필요한 패턴을 선택한다.

## 3. 게시판·최신글과 G5 고유 기능

### 3.1 게시판 표현형

| 표현형 | 용도 | 기능 경계 |
| --- | --- | --- |
| basic | 공지·일반 게시판·채용공고 | 기본 목록·본문·쓰기·댓글 계약 |
| gallery | 이미지 중심 게시판 | 썸네일 격자·이미지 확대 |
| portfolio | 수행 실적·사례 | 이미지·설명 중심 목록·상세, 기본 분류 이용 |
| webzine | 뉴스·보도 | 사진·제목·요약 목록 |
| download | 카탈로그·자료실 | G5 첨부와 다운로드 권한·횟수 표현 |
| video | 영상 자료 | 검증된 영상 링크/재생 가능한 첨부 표시. 수집 API·변환·별도 업로더 없음 |

모든 표현형에서 G5의 공지·분류·검색·페이징·답글·댓글·첨부·비밀글·비밀번호·권한·선택 작업·추천 등 해당 게시판이 제공하는 기본 동작을 보존한다. 보기 좋은 목록만 구현하고 쓰기·수정·댓글을 기본 디자인으로 남기지 않는다. 권한·저장·업로드·메일 처리는 기존 G5 흐름을 사용한다.

채용공고는 basic을 사용한다. 온라인 문의는 G5 1:1 문의(QA)를 사용하며 독자적인 inquiry 저장 기능을 추가하지 않는다. 이전 연구서의 `recruit/basic`, `inquiry`는 이 매핑으로 구체화한다.

영상 타입·메타는 실제 공개 데이터가 있을 때만 출력한다. 외부 영상 제공자의 임베드 내부 UI까지 테마가 재디자인하지 않는다. 임의 iframe·스크립트 입력을 허용하는 기능은 만들지 않는다.

### 3.2 최신글 8개 표현형

`basic`, `notice`, `image-list`, `image-grid`, `featured`, `slider`, `tabs`, `video`로 관리한다. 일반 공지·사진/요약·갤러리·포트폴리오·혼합형을 보여 준 기존 상품의 표현 범위를 참고한 출시 구성이다.

- 기본 G5의 PC·모바일 최신글 파일은 inventory에서 대응 표현형을 명시하며 빠뜨리지 않는다.
- featured는 대표 글 1개와 나머지 목록, tabs는 지정 게시판의 묶음 표현이다. 데이터 저장소나 관리자 생성기를 추가하지 않는다.
- 현재 게시판 ID·권한·링크를 입력 계약으로 전달하며 예시 `notice`, `news`를 사이트 코드에 고정하지 않는다.
- 순수 HTML 복사형에는 실시간 게시글이 들어가지 않는다. 최신글은 PHP 조합형으로 제공한다.

### 3.3 필수 G5 화면

| 영역 | 필수 포함 |
| --- | --- |
| 기본 골격 | 메인·그룹·head/tail·sub head/tail·PC/mobile 진입 경로 |
| 회원 | 로그인, 약관·가입·가입 완료, 정보수정, 회원확인, 비밀번호 찾기·재설정·확인, 프로필·폼메일, 기본 인증 연결 화면 |
| 개인 기능 | 쪽지 목록·보기·쓰기, 포인트, 스크랩·스크랩 추가 팝업 |
| 콘텐츠·지원 | 정책·약관용 내용관리, FAQ, 1:1 문의 목록·보기·쓰기·답변 |
| 탐색·현황 | 통합검색, 새글, 현재접속자, 인기검색어, 방문자, 설문·결과 |
| 공통 | 외부로그인, 최신글, 팝업, CAPTCHA, 기본 에디터 본문·쓰기 연결, 오류·권한·비밀글 확인 흐름 |
| 정책 | 개인정보·이용약관·이메일무단수집거부와 푸터 사업자 정보의 편집 가능한 예시·연결 |

현재 로컬 공식 basic의 PC·모바일 스킨 파일 목록을 확인했다. 구현 시작 시 지원 G5 버전의 전체 basic을 복제하고 파일별 `개편/그대로 상속/상품 범위 제외` inventory를 다시 만든다. 영카트 전용 파일은 명시적으로 제외하고 `theme.config.php`에도 반영한다. G5 기본 옵션으로 켠 공개 기능은 대응 화면·검사에서 누락하지 않는다.

외부 본인확인·메일·소셜 서비스의 신규 연동은 추가하지 않는다. 이미 G5에서 설정한 기본 기능은 테마가 깨뜨리지 않아야 하며, 실제 외부 호출 검증 여부는 별도로 기록한다. 폼의 실제 제출 성공 없이 외관만 보고 기능 완료라고 판단하지 않는다.

## 4. 섹션 재사용·공통 UI·효과

### 섹션 제공 범위

기존 20개 초안은 다음 **기본 역할 목록**으로 사용한다. 20개만 제공한다는 수량 상한은 폐기한다.

| 계열 | 기본 역할 |
| --- | --- |
| Intro 3 | 서브 소개, 사진·소개문, 대표 인사말 |
| Business 4 | 사진형 사업 목록, 교차 상세, 아이콘 역량, 단계별 과정 |
| Proof 3 | 실적 수치, 인증·수상, 고객·파트너 |
| Project 3 | 대표 사례, 사례 격자, 사례 슬라이더 |
| Company 4 | 비전·가치, 연혁, 조직, 복리후생 |
| Conversion 3 | 자료 다운로드 안내, 문의 CTA, 연락·방문 안내 |

75개 페이지를 구성하면서 채택한 섹션 레이아웃은 모두 카탈로그에 포함한다. 예를 들어 연혁의 다섯 배치를 하나의 고정 timeline으로 대체하지 않는다. 수량을 부풀리기 위해 같은 섹션에 다른 ID를 주지 않는다. 독립 섹션의 최종 개수는 승인된 화면을 분해한 manifest에서 산출하며, **배포 대상은 75개 페이지에서 채택한 전체 재사용 섹션**으로 고정한다.

- 정적 섹션: 런타임 밖의 복사용 블록을 완성 페이지에 복사하고 문구·링크·이미지를 교체한다.
- 동적 섹션: G5 데이터가 필요한 코드도 대상 페이지에 복사한다. 실제 두 파일 이상이 같은 기능을 공유해야 할 때만 구조 계약의 명시 허용 include로 둔다.
- 블록 원본 → 복사 주석 → 완성 페이지·미리보기·매뉴얼을 연결한다. 복사된 코드는 페이지별 독립본으로 수정한다.
- 같은 섹션 중복 삽입, 다른 페이지 이동, 순서 변경에도 CSS·버튼·효과가 독립적으로 작동해야 한다.
- 일반 페이지는 루트 `/pages/*.php` 실파일로 제공한다. 각 파일이 G5 `common.php`, 제목, 활성 테마 head, 전체 본문, tail을 직접 포함하며 코어를 수정하지 않는다.
- 모든 판매 섹션의 CSS·JS를 ZIP에 포함한다. 고객에게 재빌드를 요구하지 않는다.
- 첫 테마 내부에서 재사용하고 두 번째 테마에서 재사용이 확인된 코드만 공통 runtime package로 승격한다.

### UI와 동작

- 공통 헤더·푸터 각 1개 구현, PC 1·2단 메뉴/메가 메뉴, 모바일 드로어. 메인 패턴마다 별도 메뉴 엔진을 만들지 않는다.
- 헤더는 최상단·아래 스크롤·위 스크롤 상태를 갖는다. 메뉴가 열렸거나 내부에 키보드 포커스가 있으면 숨기지 않는다.
- 히어로는 이미지 1장 또는 최대 3장 슬라이드. autoplay 기본 OFF, 켜면 정지 조작 제공.
- Swiper 슬라이더, 이미지 확대, 탭·아코디언, 짧은 reveal·stagger·수치 보강을 제공한다.
- 패럴랙스는 지정한 장식 이미지에만 제한하며 모바일·reduced motion에서 끈다. 스크롤 가로채기·커서 효과·배경 영상 자동재생은 제외한다.
- 단일 초기화·해제 계약과 root 내부 selector를 사용한다. 복사할 때 JS 코드를 반복 삽입하지 않는다.
- JS 실패 시 본문·링크·기본 폼은 이용 가능해야 한다.

세부 버전은 [공통 표준](../standards/G5-THEME-PLATFORM-STANDARD.md)의 채택안을 기준으로 호환·보안 확인 후 catalog와 lockfile에 고정한다. 현재 루트 lockfile에 이 모든 상품 의존성이 이미 설치되어 있다는 뜻은 아니다. 새 유료 도구·외부 서비스는 추가하지 않는다.

라이트는 daisyUI `corporate`, 다크는 `business` semantic 색상으로 통일한다. 메인·75개 페이지·게시판·회원·검색·FAQ·QA·테마 팝업과 기본 에디터 출력까지 전환한다. G5 관리자 전체와 외부 제공자 iframe 내부는 테마 전환 대상이 아니다. 임의 인라인 본문 색상은 G5의 허용 범위에서 보존하며 모든 사용자 지정 색 조합의 대비를 자동 보장한다고 약속하지 않는다.

### 구매자 수정 경로

| 항목 | 공식 수정 위치 |
| --- | --- |
| 테마 주 메뉴 | G5 관리자 `환경설정 > 메뉴설정`; `get_menu_db()` 사용 |

`custom/`는 구매자가 파일로 편집하는 보존 영역이다. `custom.example/`에서 최초 한 번 복사하며, 업데이트 ZIP에 고객의 실제 `custom/` 파일을 넣어 덮어쓰지 않는다. 실행 가능한 PHP를 웹 관리자에서 입력·생성하지 않는다. 경로·권장 이미지 규격·백업·원복을 변경 위치표에 적고 고객이 minified 파일을 편집하지 않게 한다. 테마 코드가 사이트별 게시판 ID나 도메인을 고정하지 않는다.

## 6. 메타·구조화 데이터와 설정 한 화면

[출력 계획](STRUCTURED-DATA-OUTPUT-PLAN.md)을 다음 상품 범위로 적용한다.

- 게시판 목록: 현재 목록·분류·페이지에 맞는 title/OG와 `CollectionPage`·`ItemList`·`ListItem`.
- 본문: 실제 제목·공개 본문·작성자·날짜·URL·이미지에 맞는 Article/DiscussionForumPosting 및 해당 미디어.
- 댓글: 실제 공개 댓글·답글 관계에 맞는 Comment. 비밀·삭제·권한 제한 데이터 보호.
- JSON-LD는 사이트·페이지 관계, Microdata는 실제 목록·본문·댓글 DOM을 담당하고 같은 엔터티 값을 공유한다.
- 사이트 공통 문구를 모든 페이지 description으로 복제하지 않는다. 데이터가 없으면 생략하며 G5의 `wr_last`를 수정일로 쓰지 않는다.
- 일반 페이지 meta는 제목·설명·대표 이미지·제한된 페이지 타입만 받는다. `/pages/*.php`의 안정적인 페이지 ID에 매핑한다. 정책용 내용관리 페이지는 별도 ID 규칙으로 같은 출력 계약을 사용한다.
- 관리자 `환경설정 > 테마 메타·구조화 데이터` 한 화면에서 사이트 공개 정보·게시판 profile·페이지 meta를 관리한다.
- 설정은 `data/jwsoft/meta-structured/settings.json`에 저장하고 G5 코어 테이블·여분 필드를 점유하지 않는다. 최고관리자·POST token·값 검증·원자 저장을 적용한다.
- 외부 SEO 플러그인과 겹치면 테마 출력 전체 OFF를 제공한다. 자동 감지·합성은 구현하지 않는다.

공통 연구의 market/Product/Offer는 전용 장터 데이터가 있는 후속 상품을 위한 조건부 정의다. 이번 비즈니스 상품에 장터·가격·주문 기능을 추가하지 않으며 관리자에도 지원하지 않는 profile을 선택 가능하게 노출하지 않는다. 포트폴리오와 자료실에 상품 가격을 추정해 출력하지 않는다.

## 7. 매뉴얼·데모·ZIP·AI 안내

매뉴얼은 설치, 기존 상품과 분리 설치·원복, 메뉴·게시판 연결, 75개 페이지 카탈로그, 섹션 복사·교체, 변경 위치표, 메타 설정, 업데이트·복구, 자가진단, CS 범위·문의 양식, 변경 이력을 포함한다. 각 페이지와 섹션은 미리보기·입력 자료·수정 위치·적용 방법·효과·호환 버전을 제공한다.

개발자용 테마 `AGENTS.md`와 구매자 배포용 `AGENTS.md`를 구분한다. 구매자용에는 설치 파일 기준의 수정 가능 위치, 생성 자산 편집 금지, 코어 금지, 테마·라이선스·지원 범위와 수동 확인 순서를 적는다. 내부 경로·접속 정보·개발 fixture를 배포하지 않는다.

일관된 가상 기업의 문구·이미지·사업·연혁·조직·연락처로 75개 패턴을 비교할 수 있게 한다. 데이터만 바꿔 패턴 수를 채우지 않는다. 게시판 데모와 권한·실패 상태 QA fixture는 구분하며 고객 사이트에 임의 회원·글을 자동 삽입하지 않는다. 제품의 재배포 자산과 개발용 fixture도 분리한다.

설치 ZIP에는 설치 테마, 페이지·섹션 카탈로그와 예시, 완료된 CSS/JS·폰트·아이콘·허용 이미지, 수정 영역 예시, 설치·복구 안내, 라이선스·외부 고지·자산 manifest·변경 이력·checksum을 포함한다. G5 코어·Bun·Node·Composer·Docker·개발 의존성·비밀값은 포함하지 않는다. source 수정용 개발 키트는 별도 ZIP으로 제공하며 고정 lockfile, 필요한 공통 package, 구매자용 AI 헌법, 개발 계약과 setup·doctor·check 하네스를 포함한다.

2026-09-21 사용자가 추가 이미지 비교에서 실제 제작으로 진행하도록 지시했다. 6차를 첫 구현 참고로 사용하고 공통 UI와 메인부터 실제 화면에서 조정한다. 이미지 전체를 최종 승인한 것으로 간주하지 않는다. 사무실 Ubuntu 설정·배포·시험은 해당 작업의 별도 명시 지시 때 기존 환경을 확인해 수행한다.

### 출시 필수 검사

- **75개 × PC/모바일 × 라이트/다크 = 300개 기본 시각 조합** 전수 확인. 추가 폭·상태·기능 시험은 이 숫자에 별도로 더한다.
- 대표 폭 360/390/768/1440px에서 줄바꿈·잘림·메뉴·표·한국어 장문을 확인한다. 주 검수는 Mac 브라우저로 수행하고 지원 엔진/실기기 증거를 구분한다.
- G5 화면은 비회원·회원·관리자, 권한 없음·빈 상태·정상·실패·쓰기/수정/삭제·댓글/답글·비밀·첨부·검색·페이지 이동을 실제 처리한다.
- mobile 진입 경로와 강제 device 선택을 포함한다. PC 화면만 좁힌 결과로 모바일 PHP 경로 검증을 대신하지 않는다.
- 세 저장 호환 검증 유형 이후 모든 배포 섹션을 G5 저장→출력, 중복 삽입, 재배치, 업데이트 전후로 검사한다.
- 페이지마다 실제 데이터와 meta/JSON-LD/Microdata가 일치하고 보호 데이터가 노출되지 않아야 한다. 설정 실패 시 기존값을 보존한다.
- `bun run check` 등 기존 gate와 구현 단계에 추가한 PHP·build·자산·카탈로그·실제 화면·ZIP gate를 구분해 기록한다. 존재하지 않는 검사를 실행한 것으로 보고하지 않는다.
- 기존 성능 예산을 유지하고 비용이 큰 시각 효과는 먼저 줄인다. 고정 색상으로 라이트·다크를 우회하지 않는다.
- 최초 설치·구매자 수정 후 업데이트·원복에서 custom 파일·내용관리 데이터·메타 설정이 보존되어야 한다.
- 매뉴얼 경로·복사 코드와 실제 ZIP 버전이 맞고 사용 절차를 재현해야 한다. 정적 검사 통과만으로 판매 완료라고 하지 않는다.

검사 실패는 완료 조건 미충족이며 기능을 조용히 제외하는 근거가 아니다. 범위 변경이 필요하면 페이지 카탈로그·상품 설명·매뉴얼·검사표를 함께 수정해 별도 결정으로 남긴다.
