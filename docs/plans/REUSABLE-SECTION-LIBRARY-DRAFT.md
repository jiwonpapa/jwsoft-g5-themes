# JW-Business 복사용 섹션 라이브러리 초안

- 최초 작성: 2026-09-21
- 구조 개정: 2026-09-22
- 상태: 복사용 자료 설계. 런타임 include 라이브러리가 아님
- 적용 계약: `themes/business/jw_business/docs/STRUCTURE-CONTRACT.md`

## 1. 목적

메인 5종과 일반 페이지 70종에서 사용한 섹션을 구매자가 참고·복사할 수 있게 정리합니다.
기존 초안의 page renderer, recipe, section partial, 자동 route 생성 방식은 폐기했습니다.
그누보드5 테마 사용자가 새로운 런타임 구조를 학습하지 않도록 모든 판매 페이지를 독립 PHP
파일로 제공합니다.

## 2. 사용 원칙

1. 필요한 블록 원본을 런타임 밖의 `blocks/`에서 고릅니다.
2. 홈은 선택한 `index_N.php`, 일반 페이지는 웹루트 `/pages/*.php`에 코드를 복사합니다.
3. 복사 위치에 원본 경로와 독립 수정본이라는 주석을 남깁니다.
4. 복사 후에는 대상 페이지 안에서 직접 수정합니다. 원본 변경을 자동 전파하지 않습니다.
5. CSS·JavaScript는 판매 ZIP에 빌드된 상태로 포함하며 고객 서버 빌드를 요구하지 않습니다.

```html
<!--
JW BLOCK COPY: blocks/business/photo-grid-01.php
현재 페이지에 복사된 독립 코드입니다. 원본 변경은 자동 반영되지 않습니다.
-->
```

## 3. 파일 구조

```text
themes/business/jw_business/
├── blocks/                       # 복사용 원본. 런타임 include 금지
│   ├── home/
│   ├── company/
│   ├── business/
│   └── conversion/
├── src/php/
│   ├── index.php                 # 실제 홈
│   ├── index_1.php … index_5.php # 선택용 완성형 홈
│   ├── head.php
│   ├── tail.php
│   └── inc/                      # 명시 허용한 공용 메뉴만
├── pages/                        # 웹루트에 설치할 완성형 일반 페이지 70개와 카탈로그
├── docs/manual/
└── docs/STRUCTURE-CONTRACT.md
```

판매 ZIP에서는 `theme/jw_business/`와 웹루트 `pages/`를 각각 원래 위치에 설치합니다.

## 4. 완성 페이지 계약

### 홈

- 실제 진입점은 `theme/jw_business/index.php`입니다.
- 선택용 홈은 `index_1.php`~`index_5.php`이며 각 파일에 head 호출, 전체 본문, tail 호출이 있습니다.
- 홈 변경은 선택 파일을 `index.php`로 복사하는 방식입니다.
- 홈 본문용 partial이나 동적 renderer를 만들지 않습니다.

### 일반 페이지

- 주소는 `/pages/<page-id>-<1~5>.php`입니다.
- 각 파일은 `../common.php`, `$g5['title']`, 테마 head, 전체 본문, 테마 tail을 직접 가집니다.
- ID만 넘기는 wrapper와 공통 page dispatcher를 만들지 않습니다.
- 메인 5종은 `/pages/home-N.php`로 만들지 않습니다.

## 5. 공용 include 경계

여러 화면에서 실제로 함께 쓰는 메뉴·모바일 메뉴와 구조 계약에 등록된 다중 소비 스킨 조각만
include할 수 있습니다. 새 include는 두 곳 이상의 실제 소비가 확인되고, 호출 위치가 구조 검사기의
허용 목록에 고정되어야 합니다.

공개 메뉴는 G5 관리자 메뉴 DB의 `get_menu_db()`를 사용합니다. 별도 `navigation.php`, 메뉴 JSON,
페이지 카탈로그 기반 메뉴 생성은 허용하지 않습니다.

## 6. 블록 분류

| 계열 | 기본 역할 |
| --- | --- |
| Intro | 서브 소개, 사진·소개문, 대표 인사말 |
| Business | 사진형 사업 목록, 교차 상세, 아이콘 역량, 단계별 과정 |
| Proof | 실적 수치, 인증·수상, 고객·파트너 |
| Project | 대표 사례, 사례 격자, 사례 슬라이더 |
| Company | 비전·가치, 연혁, 조직, 복리후생 |
| Conversion | 자료 안내, 문의 CTA, 연락·방문 안내 |

이 목록은 역할 분류이며 판매 수량을 부풀리는 기준이 아닙니다. 서로 다른 페이지는 데이터만
바꾼 동일 마크업이 아니라 읽기 순서와 정보 구조가 달라야 합니다.

## 7. 블록 문서

각 복사용 블록은 다음 정보를 제공합니다.

- 블록 ID와 원본 경로
- PC·모바일·라이트·다크 미리보기
- 교체할 문구·링크·이미지
- 필요한 CSS class와 `data-jw-*` 동작 선택자
- 같은 페이지에 중복 사용 가능한지 여부
- 긴 한국어 문구, 이미지 누락, 항목 수 변화 시험 결과
- 지원 테마와 최소 버전

PHP 코드 예시는 완성 페이지에 붙여넣을 수 있는 형태로 제공합니다. 예시를 보여 주기 위한 escape
복제본과 실제 배포 코드가 달라지지 않게 checksum을 기록합니다.

## 8. 검증

- `bun run structure:check`: partial·dispatcher·wrapper·임의 include 재도입 차단
- 각 홈과 일반 페이지의 PHP 문법 검사
- 360/390/768/1440px, 라이트·다크, 키보드, reduced motion 확인
- 블록 중복 삽입과 순서 변경 시 selector·ID 충돌 확인
- G5 관리자 메뉴 변경이 PC·모바일 메뉴에 반영되는지 확인
- 판매 ZIP 새 설치·업데이트·원복 및 고객 서버 무빌드 설치 확인

구조 검사 통과는 화면 디자인 완성이나 실제 G5 기능 검증을 대신하지 않습니다.

## 9. 업데이트 정책

복사된 페이지 코드는 구매자 소유의 독립 수정본이므로 라이브러리 변경을 강제로 덮어쓰지 않습니다.
업데이트에서 필요한 변경은 블록 ID, 영향 파일, 수동 반영 방법을 변경 이력과 매뉴얼에 제공합니다.
공통 런타임으로 승격하는 코드는 두 개 이상의 테마에서 실제 재사용과 호환성이 확인된 뒤 별도
결정합니다.
