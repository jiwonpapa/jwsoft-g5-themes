# JW-Business 메인 메뉴 재설계안

2026-09-23 · 범위: 메인 #1~#4와 메인 메뉴의 원페이지 3종 · 상태: **2026-09-26 구현·개발 사이트 반영, 판매 품질 차단 미통과**

7개 페이지의 구현·배포 결과와 남은 차단 항목은 [2026-09-26 검토 보고](../reports/JW-BUSINESS-MAIN-SEVEN-IMPROVEMENT-2026-09-26.md)를 따릅니다. 아래 설계 순서는 최초 실행 계획이며 품질 승인 기록이 아닙니다.

후속 지시로 개선 범위가 상위 메뉴 전체로 확대되었다. 이후 묶음 순서와 메뉴 표시 기준은 [전체 메뉴·페이지 개선 실행 기준](JW-BUSINESS-FULL-MENU-IMPROVEMENT-2026-09-23.md)을 따른다. 메인 #1의 예약 화면은 제공 범위와 어긋나므로 기업 웹페이지의 반응형 디자인 시안으로 교체한다.

현재 화면의 판매 가능 판정은 [전체 메뉴 시야 점검](../reports/JW-BUSINESS-FULL-MENU-VISUAL-AUDIT-2026-09-23.md)의 **불가**를 유지한다. 이 문서는 화면 완성 또는 품질 검사 통과 기록이 아니다. 메인 #5 제거 전 제작한 8종 스토리보드는 현재 기준에서 폐기했습니다. 해당 구상은 첫·중간·끝의 면적과 읽는 방식만 보여 주며, 실제 사진·완성 시안은 아니다.

## 설계 결정

판매 화면을 7개의 다른 *용도와 읽는 방식*으로 만든다. 헤더·메뉴·푸터, G5 경계, Pretendard, `jw-light`/`jw-dark`와 의미 색상 토큰은 유지한다. 공통 시스템은 글꼴·간격·포커스·버튼·컨테이너에 한정한다. 본문은 공통 카드/섹션 렌더러로 묶지 않고 독립 PHP에서 구성한다. 페이지별 사진·디지털 화면·제품 렌더는 해당 페이지 소유로 만든다. 번호, 섹션 순서, 배경색만 다른 화면은 채택하지 않는다.

메인 #1·#2의 슬라이더와 제품형의 Blender 36프레임은 사용할 수 있는 기존 기술 자산이다. 좋은 *장면*을 만드는 것은 별개다. 메인 #3~#4에 슬라이더를 복제하지 않으며, Apple식 스크롤 장면은 제품 설명에 한 번만 사용한다. 애니메이션은 이미지·정보의 관계를 이해시키는 곳에만 둔다. 모바일·`prefers-reduced-motion`에서는 같은 내용을 정적 화면으로 볼 수 있어야 한다.

## 먼저 만들 이미지 기반 섹션 기준판

현재 스토리보드는 색면으로 **구조만** 확인하는 초안이다. 실제 디자인 기준은 사진·화면 자료가 들어간 다음 7개의 섹션 시안으로 만든다. 각 시안은 PC 1440px와 모바일 390px를 한 쌍으로 제작하고, 이미지의 출처/페이지 소유, 제목과 본문의 실제 길이, 첫 화면 또는 앞뒤 섹션과의 연결을 적는다. 이 시안은 구매자가 조합하는 런타임 블록 라이브러리가 아니라 **제작자가 페이지 전체를 설계할 때 비교하는 시각 기준판**이다.

## 메인 #1의 구현용 화면 명세 — 첫 검증 대상

1. **첫 화면 / 3장 슬라이더.** PC에서는 헤더 아래 70~85vh 안에 주제·한 문장·CTA·장면 선택 01/02/03·이전/다음·재생/정지를 모두 둔다. ① 전략: 사람이 실제 의사결정 지도를 보는 장면, ② 디지털: 사용 맥락과 읽을 수 있는 실제 HTML 화면, ③ 브랜드: 하나의 데모 브랜드에 속한 실물 결과를 보여 준다. 세 장은 같은 가상 에이전시가 만든 서로 다른 결과로 연결하고 피사체·카메라 거리를 바꾼다. 모바일에서는 각 장면의 세로 크롭 또는 전용 세로 프레임을 지정하고 텍스트 안전 영역을 검수한다. 기존 `data-jw-hero-slider`와 `home-one.ts` 동작을 사용한다.
2. **서비스 목차 / 큰 아이콘.** 비즈니스 전략·디지털 서비스·브랜드 경험의 Lucide 아이콘을 제목 **위·가운데** 배치한다. 세 개의 링크는 각기 아래 이야기로 이동한다. 아이콘만 회전하고 텍스트·카드는 회전하지 않는다. hover와 키보드 focus에 같은 반응을 주며 reduced-motion에서는 회전하지 않는다. 기존 `.jwh1-service-icon svg` 계약 수량 3을 유지한다.
3. **중간 / 세 가지 다른 증명.** 전략은 크게 그린 로드맵과 짧은 의사결정 문장, 디지털은 실제 HTML로 그린 반응형 기업 웹페이지 디자인 시안, 브랜드는 전용 실물 사진의 세로/가로 조합으로 구성한다. 예약·관리 대시보드처럼 제공하지 않는 기능을 시연하는 화면은 쓰지 않는다. 한 구간을 CSS만 바꿔 세 번 반복하지 않는다. 데모 수치와 사례명은 샘플임을 화면/문서에 일관되게 표기한다.
4. **후반 / 한 사례의 결론.** 하나의 가상 고객 맥락으로 문제 → 적용 화면 → 확인 가능한 결과 형태를 보여준다. 실적 수치가 검증되지 않으면 가짜 퍼센트를 넣지 않는다. 팀 사진은 이 사례의 참여자 같은 서사에만 사용한다.
5. **마지막 / 다음 행동.** 뉴스 미리보기는 실제 G5 latest를 사용한다. 상담 CTA는 사용자가 무엇을 준비해 연락할지 짧게 알리고 기존 G5 문의 경로로 보낸다. 반복 회색 띠 대신 배경과 글자 규모를 처음 장면의 마무리로 설계한다.

메인 #1의 변경 파일은 `src/php/index_1.php`, `src/styles/home-one.css`, `src/scripts/home-one.ts`, `src/scripts/home-one-entry.ts`, 해당 페이지 전용 이미지와 `quality/assets.json`이다. 필요한 경우에만 token 원본을 바꾸고 생성물을 빌드한다. 기존 수정 작업과 충돌하지 않도록 현재 diff를 먼저 확인한다. G5 코어·DB·헤더/메뉴·다른 일반 페이지는 건드리지 않는다.

현행 `quality/contract.json`의 메인 #1 필수 **슬라이더 3장·큰 아이콘 3개·모션과 접근성 동작**은 유지한다. 기존에 적힌 ‘정밀 기술’ 사진 문구는 새 디자인의 ‘전략 판단 장면’과 맞지 않으므로 구현 때 실제 화면에 맞게 계약 설명을 갱신한다. `ready`나 검사 예외를 먼저 바꾸지 않는다.

나머지 구현 경로도 기존 구조에 맞춘다. #2는 `src/php/index_2.php`·`src/styles/home-2.css`·`src/scripts/home-2.ts`, #3~#4는 각각의 `src/php/index_N.php`와 현재 공통 번들에 들어가는 `src/styles/home-variants.css`를 수정한다. #4의 단계 표시처럼 JS가 실제로 필요한 경우에만 페이지 조건부 모듈을 `src/scripts/theme.ts`에 연결한다. 원페이지 PHP는 상품 웹루트 `pages/onepage-*.php`에 둔다. 소스 `onepages/assets/onepages.css`·`onepages.js`는 Vite의 `onepages-entry.ts`로 빌드하고, 이미지·36프레임은 테마 payload에 복사한다. 페이지별 CSS 규칙은 스코프를 분리하며 형제 페이지에 같은 섹션 스타일을 강제로 적용하지 않는다.

모바일에서 단순 1열 복제로 수렴하지 않도록 별도 흐름을 둔다. #1은 세 장면 각각 세로 크롭과 3개 아이콘 목차, #2는 질문을 먼저 읽고 해당 산출물을 바로 보게 하는 분할 해제, #3은 대표 작업 뒤 크기가 다른 사례 이미지와 번호, #4는 sticky를 풀어 `단계→산출물`의 자연스러운 세로 문서. 제품 원페이지의 프레임 회전은 정적 포스터/상세 사진으로 대체하고, 서비스 목차는 가로 이동 가능한 앵커, 프로젝트 갤러리는 스와이프와 보이는 버튼을 제공한다.

## 이미지·자료 제작 규칙

기존 메인 전용 사진 7장을 직접 확인한 결과, 파일 소유가 분리되어 있다는 사실만으로 디자인에 적합하지 않다. 메인 #1의 `digital.webp`는 휴대폰을 보는 인물뿐이라 디지털 **결과물**이 안 보이고, `technology.webp`는 로봇 제조 현장이라 사업 전략을 설명하지 못한다. `brand.webp`의 차 포장과 `team.webp`의 인테리어 재료 검토는 하나의 에이전시 서사로 이어지지 않는다. 메인 #2의 `strategy.webp`는 다시 건축/공간 보드가 보이고, `digital.webp`의 화면은 읽을 수 없는 사진 속 UI이며, `operations.webp`는 호텔 접객 장면으로 서비스 업종이 갑자기 바뀐다. 따라서 **7장을 메인 재설계의 최종 자산으로 승인하지 않는다.** 원본 파일은 삭제하지 않고 사용 여부를 새 시안에서 결정한다. 필요한 것은 `프롬프트가 다른 사진`이 아니라 해당 페이지의 사례·산출물과 내용이 맞는 새 장면이다.

새 자산의 숫자는 사진 개수가 아니라 **장면 역할**로 산정한다. 아래는 디자인 구현에 필요한 최소 원본 세트다. 같은 페이지의 PC/모바일 크롭은 한 원본으로 셀 수 있다. 서로 다른 페이지는 원본을 공유하지 않는다.

| 화면 | 원본 자료의 최소 구성 |
| --- | --- |
| 메인 #1 | 새 히어로 3장(전략·디지털·브랜드) + 같은 데모 회사의 팀 장면 1 + 전략 도식 1 + 읽을 수 있는 HTML 디지털 화면 1 + 브랜드 실물 상세 1. |
| 메인 #2 | 새 히어로 3장(진단·설계·운영) + 질문별 산출물 3종 + 확대 가능한 HTML 디지털 화면 1. |
| 메인 #3 | 대표 작업 1건의 첫 장면 1 + 서로 다른 사례 3건의 전용 결과 자료를 각 2개 이상. 실물 사진과 화면 자료 혼합. |
| 메인 #4 | 네 단계 각각 다른 실제 데모 산출물 4. 필요 시 단계 현장 사진 1~2, 사진 없이도 설득 가능하도록 먼저 설계. |
| 제품 원페이지 | 기존 동일 모델 Blender 원본/36프레임 유지 + 동일 제품의 연결부·소재·설치 또는 사용 맥락을 보여 주는 새 렌더 3장. |
| 서비스 원페이지 | 전용 상담 현장 1 + 서비스 단계별 산출물/화면 3 + 사례 시각 자료 1. |
| 프로젝트 원페이지 | 동일 프로젝트에서 유래한 전경·동선·재료·디테일 최소 4장과 맥락/도면 1. 현재 다른 공간을 섞은 사진은 제외. |

각 시안 이미지에는 용도, 프롬프트 또는 제작원, 원본 파일, 파생 크롭, `owner`, SHA-256과 `origin`을 기록한다. 원본이 없는 외부 검색 사진을 임의로 끼우지 않는다. 필요하면 imagegen 또는 기존 Blender 장면에서 제작하되, **서로 다른 사진을 같은 원본처럼 이름만 바꾸지 않는다**. 이미지 적합성·유사도는 목록 검사와 실제 첫·중간·끝 캡처에서 모두 확인한다.

## 구현 수단과 순서

1. **이미지 기준판과 메인 #1 시안.** 위 A~H 패턴을 실제 자료가 들어간 PC 1440px·모바일 390px 한 쌍으로 만들고 메인 #1부터 첫·중간·끝을 연결한 고해상도 시안을 만든다. 메인 #1에서는 슬라이드 3컷, 아이콘 목차, 전략 도식, 읽을 수 있는 디지털 화면, 브랜드 실물, 사례 마무리를 한 화면 흐름으로 확인한다. 빈 회색 박스나 기존 건물 사진을 시안 완료로 취급하지 않는다.
2. **메인 #1 1차 구현.** 독립 PHP 본문을 재구성하고 기존 슬라이더·모션을 목적에 맞게 수정한다. JS가 꺼져도 첫 슬라이드, 세 서비스와 사례가 읽히고, motion이 줄어들어도 정보가 사라지지 않게 한다. `theme/` 생성 파일은 직접 수정하지 않는다.
3. **메인 #1 실제 화면 판정.** 로컬 build/structure/quality 검사를 실행한 후 개발 화면 반영은 별도 지시 경계를 지킨다. 반영된 화면을 Codex 내장 브라우저에서 PC·모바일, 라이트·다크의 전체 길이와 첫·중간·끝, 슬라이더/아이콘/스크롤 동작으로 확인한다. 사진의 내용 적합성까지 판단한다. 형님께는 이 실제 화면을 먼저 보여 드려 방향을 판단받는다. 이 단계의 메인 #1 통과는 4종 묶음 완료를 뜻하지 않는다.
4. **나머지 3개 홈 구현.** #2의 분할 슬라이더, #3의 포트폴리오, #4의 산출물 과정을 서로 다른 본문/사진으로 제작한다. 한 페이지 완료 때마다 전체 홈 4종을 첫 화면과 중간 구도로 나란히 비교하고 반복을 수정한다.
5. **원페이지 3종.** 기존 제품형 3D 기술은 살리고 서비스·프로젝트는 전용 자료를 다시 만든다. 원페이지는 현재 별도 배포본이므로 판매 ZIP에 포함되도록 상품 manifest/패키징 경로를 연결한 뒤 설치·업데이트·롤백을 따로 검사한다. 그 전에는 판매 구성으로 주장하지 않는다.
6. **품질 차단.** `bun run quality:check`와 홈 4종의 `quality:prepare home`/`quality:compare home`/`quality:complete home`을 기존 절차대로 수행한다. PC·모바일 × 라이트·다크의 홈 16장 전체 화면과 6쌍 비교, 독립 시야 검토가 필요하다. `ready` 플래그나 검사 예외를 먼저 고쳐 통과시키지 않는다. 원페이지의 동등한 캡처/상품 포장 검증도 별도로 기록한다.

## 실패 판정 기준

메인 4종의 첫 화면을 제목을 가리고 봤을 때 3종 이상이 같은 구도면 실패다. 중간을 섞었을 때 사진·카드·연회색 구획의 출처를 구분하기 어려우면 실패다. 디지털 서비스의 대표 자료가 회의실 사진이면 실패다. 동일 원본 사진을 다른 페이지에 다시 쓰면 실패다. 모바일에서 모두 `제목 → 설명 → 사진 → 카드 → CTA` 순서로 평탄화되면 실패다. 인터랙션만 화려하고 사진·내용의 역할이 맞지 않아도 실패다. 이 조건을 통과하고 실제 화면의 완성도가 비교 기준에 도달할 때만 판매 가능을 다시 판정한다.

## 범위

이 설계는 메인 메뉴의 7개 화면에만 적용한다. 일반 하위 페이지 70종의 현재 판매 불가 판정은 그대로다. 메인만 좋아져도 전체 테마를 판매 가능이라고 주장할 수 없다. 메인 #1이 형님의 시야에서 방향을 통과한 뒤 같은 원칙을 다른 메뉴 묶음에 적용한다.
