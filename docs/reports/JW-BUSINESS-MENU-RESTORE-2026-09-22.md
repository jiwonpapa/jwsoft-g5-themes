# 전체 메뉴 복구와 작업 중단

2026-09-22 · 사용자 지시: 전체 메뉴를 처음 구조로 복구하고 현재 단위를 마무리한 뒤 중단.

## 복구 결과

G5 DB 전환 과정에서 하위 분류를 없애고 긴 한 열로 만든 회귀를 수정했습니다. PC의 스크롤 목록을 다열 분류로, 모바일의 긴 목록을 대분류·하위 아코디언으로 되돌렸습니다.

| 대분류 | 복구한 하위 구성 | 목적지 |
| --- | --- | --- |
| 메인 | 완성형 홈 1~5 | 5 |
| 회사소개 | 기업개요·대표 인사말·비전·연혁·조직도·인증·위치 | 35 |
| 사업분야 | 목록·상세·프로세스 | 15 |
| 프로젝트 | 프로젝트 갤러리·자유게시판 | 2 |
| 인재채용 | 인재상·복리후생 | 10 |
| 고객지원 | 고객센터·연락처/문의 5종씩, 공지·FAQ·1:1 문의 | 13 |

기존 구조의 목적지는 모두 복구했습니다. PC 전체 80개 하위 링크이며, 모바일은 현재 기본 홈 안내 링크가 별도로 있습니다. G5 관리자 메뉴 DB를 계속 원본으로 사용하고, 별도 catalog나 runtime partial을 되살리지 않았습니다. 화면 그룹화 함수는 데이터만 반환합니다. 일반 메뉴·외부 링크·관리자 숨김·순서를 보존합니다.

## 확인한 증거

- 실제 G5 PC: 900/1024/1440px × 라이트/다크 × 6대분류 = 36건. 모두 표시되고 내부 세로 스크롤·화면 밖 하위 링크 없음.
- 실제 G5 모바일: 360/390px × 6대분류. 가로 넘침 없음, 분류·하위 펼침·Escape 닫기·포커스 복원 확인. 모바일은 필요한 하위 분류를 펼쳐 읽는 방식이며 모든 메뉴를 한 화면에 동시 표시한다는 뜻은 아닙니다.
- 캡처: `output/playwright/menu-restoration/desktop-{0..5}.png`, `mobile-{0..5}.png`, `matrix.txt`. PC·모바일 12장을 직접 확인했습니다. 로컬 근거이며 Git에는 넣지 않습니다.
- 테마 check: 구조·token·타입·build·39 tests / 233 assertions 통과. 루트 기반 check 통과.
- 실제 PHP 8.3: 두 메뉴 include와 공용 library lint, 순수 데이터 회귀 검사 통과.
- 하위 링크 80개를 실제 G5로 요청해 모두 HTTP 200/PHP 오류 없음 확인. 페이지 구현 완료 증거가 아니라 메뉴 목적지 연결 검사입니다.
- 독립 Impeccable 검수: `ship`, 전체 메뉴 복원 범위. 수동 감지 결과 빈 목록. 회사소개 본문이나 전체 테마 품질 승인으로 확대하지 않습니다.
- 문서화 검수는 원래 메뉴·현재 PHP·CSS를 대조했고 기존 색·서체·패널·모바일 control을 유지한 복구임을 확인했습니다. 전역 디자인 문서는 변경하지 않았습니다.

## 개발 환경 변경·보호

이 작업이 넣었던 83개 개발 메뉴와 DB 현재 값이 정확히 일치하는지 확인한 뒤, 원래 프로젝트·공지·고객지원 내 문의까지 포함한 86개 행(6대분류+80목적지)으로 복구했습니다. 관리자 변경이 발견되면 중단하도록 제한했습니다. 이전 행 백업은 서버 `backups/jw-menu-before-restore-20260922-062528.json`에 보관했습니다. 테마·페이지 파일의 이전 백업도 유지했습니다.

운영 사이트·G5 코어·스키마·서버 설정은 변경하지 않았습니다.
