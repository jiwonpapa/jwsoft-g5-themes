# JW-Business 실제 화면 시각 검증

## 후속 개선 반영

사용자의 개선 지시에 따라 아래 항목을 수정하고 기존 개발 사이트에 반영했습니다. 아래 최초 검토 기록은 수정 전 증거로 보존합니다.

| 항목 | 변경 후 실제 확인 |
| --- | --- |
| PC 이름/닉네임 | 높이 모두 48px, 같은 행의 top 모두 715px로 일치 |
| CAPTCHA | 입력칸 48px, 음성·새로고침 버튼 44px. 가입·계정 찾기·글쓰기·댓글에서 사용하는 `data-jw-captcha` 공통 스타일. 모바일에서는 입력칸을 한 줄 전체로 배치 |
| 다크 | 입력 테두리, placeholder, 필수 표시·댓글 수·회원가입 링크의 색상 역할 개선. daisyUI 변수만 사용 |
| 제목·여백 | 기능 화면의 PC 큰 제목을 32px로 조정. 글쓰기 내부 중복 제목은 접근성 트리에 유지하면서 시각적으로 숨김 |
| 갤러리 | 1440×1000에서 첫 이미지 시작 위치 약 513px → 406px |
| 첨부 | 기본 file input을 유지하고 선택 버튼·파일명 표시 스타일 통일. 바이트 대신 파일당 최대 MB/KB 표시 |
| 댓글 | 본문 14px → 16px, 작업 버튼 36px → 44px |

실제 Edge에서 PC 글쓰기 상하단·가입 폼·CAPTCHA·갤러리, 모바일 다크 가입·CAPTCHA·로그인·댓글을 다시 확인했습니다. 확인한 모바일 가입·댓글과 PC 갤러리에서 가로 넘침이 없었습니다. 관리자 로그인과 라이트/PC 보기, 뷰포트는 검증 후 복원했습니다.

테마 `bun run check`의 16 tests·typecheck·build·산출물 검사, 수정 PHP 문법 검사, 수동 Impeccable 감지를 통과했습니다. CAPTCHA 풀이·실제 신규 가입, 실제 첨부 업로드 및 상품 사진 교체는 이번 확인에 포함하지 않습니다. 시험용 갤러리 이미지는 유지했습니다.

브라우저가 반환한 OKLCH 전경/배경 값을 선형 sRGB 상대 휘도로 환산하여 확인한 대비: 다크 입력 테두리 3.30:1, 다크 필수 표시 11.49:1. 이는 해당 색 조합의 측정이며 사이트 전체 접근성 인증을 뜻하지 않습니다.

---

2026-09-21, 개발 사이트 `https://g5themes.test/`를 Edge에서 직접 열어 확인했습니다. 이번 작업은 검토·보고이며 테마 코드 수정과 배포는 하지 않았습니다.

## 판정

기능 화면의 기본 연결과 색상 전환은 갖췄지만, 판매용 테마의 시각적 완성도는 아직 미달입니다. 특히 회원가입 필드 정렬, CAPTCHA 스타일 누락, 다크 화면의 입력 경계와 강조 글자 구분을 먼저 수정해야 합니다. 앞선 기능 개선 보고에서 이 결함들을 충분히 확인하지 못했습니다.

## 직접 본 범위

- PC 1440×1000: 갤러리, 자유게시판 목록·본문·댓글, 글쓰기 상하단, 가입 정보 입력 상하단, 계정 찾기, 로그인.
- 모바일 390×844: 갤러리 라이트, 본문·댓글 다크, 로그인 다크, 약관·가입 정보 입력과 CAPTCHA 다크.
- 가입 약관 전체 동의 후 정보 입력으로 실제 이동했습니다. 회원가입 제출·CAPTCHA 풀이·메일 전송은 하지 않았습니다.
- 가입 완료와 비밀번호 재설정 성공 화면은 이번 직접 시각 검증에 포함하지 않았습니다. 이전 렌더 검사를 이번 브라우저 검증으로 계산하지 않습니다.
- 검토 후 기존 관리자 로그인, 라이트 모드, PC 기기 설정과 브라우저 크기를 복원했습니다.

## 우선 개선 사항

| 우선순위 | 관찰한 문제 | 개선 방향 / 완료 조건 |
| --- | --- | --- |
| 1 | PC 회원가입의 이름 입력칸은 높이 79px, 닉네임은 46px. 같은 행인데 시작선도 약 32px 차이 | 필드의 라벨·입력·도움말 배치를 분리하고 입력 높이를 통일. 도움말 길이가 다른 경우에도 양쪽 입력 상단·높이가 같아야 함 |
| 1 | 가입과 계정 찾기의 CAPTCHA에 기본 fieldset·버튼 모양이 남음. 가입 입력칸 65×25px, 음성/새로고침 버튼 높이 22px | CAPTCHA 검증 계약은 보존하고 표시 컴포넌트를 공통화. 입력칸을 알아보기 쉽게 확대하고 버튼 터치 영역을 44px 이상 확보. 이미지·입력·보조 버튼·설명 분리 |
| 1 | 다크 로그인·가입·댓글에서 입력칸과 배경 경계가 약함. 필수 표시·댓글 수·회원가입 링크의 파란 글자가 어두움 | 승인된 daisyUI 색상 변수 안에서 텍스트와 표면 역할을 재배정. 어두운 primary를 작은 글자에 그대로 쓰는 조합 수정. 실제 전경/배경 대비 측정 후 확인 |
| 2 | 글쓰기에서 ‘자유게시판 글쓰기’ 아래 ‘새 글 쓰기’가 반복됨. 페이지 제목 약 54px, 내부 제목 약 35px인데 라벨은 13px | 작업 화면의 제목을 간소화하고 상단 공간 축소. 제목·본문·라벨·도움말의 공통 크기 단계 재정리 |
| 2 | PC 갤러리 첫 이미지가 화면 상단 약 513px부터 시작. 모바일에서도 분류·개수·관리 작업·정렬이 여러 줄을 차지 | 상단 제목/필터/도구 영역을 정돈해 첫 콘텐츠 노출을 앞당김. 여백을 일괄 삭제하지 말고 정보 사이 간격만 조정 |
| 2 | 글쓰기 첨부파일은 회색 기본 파일 선택 UI이고 주변 버튼과 다름. 용량이 ‘1,048,576 바이트’로 표시됨 | 기본 file input 동작을 유지하면서 선택 버튼·파일명·용량 안내를 통일. 고도화 업로더 추가 없이 ‘최대 1 MB’처럼 읽기 쉬운 단위 사용 |
| 2 | 댓글은 본문 14px, 날짜 12px, ‘댓글 작업’ 버튼 높이 36px. 모바일에서 작은 정보와 작업 버튼이 반복됨 | 댓글 본문을 더 읽기 쉽게 조정하고 보조정보 대비 확보. 작업 버튼 터치 영역 확대, 본문 가까이에 일정한 위치로 배치 |

위 픽셀값은 해당 검증 뷰포트의 실제 DOM 계산값입니다. 대비 부족은 이번 육안 판정이며 WCAG 수치 검사를 통과/실패했다고 단정하지 않습니다.

## 유지할 부분

- 갤러리 PC 3열·모바일 1열의 기본 구조와 이미지 비율은 안정적입니다.
- 가입 3단계 표시는 현재 단계를 알아보기 쉽습니다.
- 라이트 로그인 화면은 입력과 주요 동작의 배치가 비교적 정돈돼 있습니다.
- 공통 파란 주요 버튼, 폼 모서리, 헤더·푸터를 유지하면서 기능 화면을 정돈할 수 있습니다. 전면 재디자인보다 공통 폼과 텍스트 규칙 수정이 우선입니다.

## 갤러리 콘텐츠 평가의 한계

현재 이미지는 색 면을 반복한 시험용 데이터입니다. 배열과 반응형은 볼 수 있지만 실제 프로젝트 사진의 크롭, 가로·세로 혼합, 사진 없는 글과 긴 제목 조합까지 상품 수준으로 검증한 것은 아닙니다. 사진형 예시 데이터로 별도 확인해야 합니다.

## 권장 작업 순서

1. 필드 높이·정렬 + CAPTCHA 공통 스타일 + 다크 대비.
2. 중복 제목·상단 공간 + 타이포그래피 + 댓글 작업 크기.
3. 파일 선택 UI + 실제 사진을 사용한 갤러리 구성 검증.

1순위 수정 후 같은 PC·모바일 화면으로 확인하고, 실제 가입 완료 화면의 시각 검증을 별도로 마무리해야 합니다.
