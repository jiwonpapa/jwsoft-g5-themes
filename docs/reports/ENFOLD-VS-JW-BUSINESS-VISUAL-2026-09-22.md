# Enfold와 JW-Business 직접 시야 비교

작성일: 2026-09-22. 대상: [Enfold 공개 데모](https://kriesi.at/themes/enfold-2017/), [현재 JW-Business 개발 사이트](https://g5themes.test/).

## 판단

**현재 JW-Business는 Enfold와 비교하면 시각 구성의 폭, 콘텐츠의 구체성, 페이지 간 연결 완성도가 부족합니다. 최신 기술을 채택했다는 사실로 이 격차를 설명하거나 상쇄할 수 없습니다.**

기업개요 5종은 실제로 서로 다른 배치입니다. 그러나 세 장의 사진과 비슷한 메시지를 반복해 사용하는 수준에서 벗어나지 못했습니다. Enfold는 섹션마다 이미지의 역할, 정보의 형식, 크기와 비율, 읽는 동작을 다르게 만듭니다. 형님께서 요구하신 “여러 섹션을 조합해 서로 다른 일반 페이지를 만드는 것”에 더 가까운 시연입니다.

다만 비교 대상의 상태는 구분해야 합니다. Enfold는 완성된 판매 데모이며 JW는 개발 중입니다. JW의 70개 파사드는 먼저 껍데기와 링크를 연결하라는 지시에 따른 중간 산출물입니다. 이를 70개의 불량 완성품으로 평가하지 않습니다. 동시에 이 상태를 75개 레이아웃 완성으로 표현해서도 안 됩니다.

## 검토 범위와 근거

상단 메뉴를 펼쳐 각 목적지를 클릭하고 스크롤한 실제 브라우저 관찰을 우선했습니다. JW는 현 소스와 실제 화면을 대조했습니다. 구현·빌드·배포·데이터 변경은 하지 않았습니다.

**Enfold는 상단 탐색 링크 95개를 클릭했고 중복을 제외한 87개 목적지를 확인했습니다. 장바구니·푸터 4개를 더해 총 91개 목적지의 화면을 검토했습니다.** 검색 열기와 모바일 메뉴 열기도 별도로 조작했습니다. SNS의 외부 홈페이지, 본문 속 모든 링크·모든 슬라이드, 모든 개별 글과 다른 데모까지 재귀 탐색한 것은 아닙니다.

| Home·Features·Pages 일반/독립 페이지·검색 | 14 |

PC는 1440×1000에서 검토했습니다. 모바일은 390×844에서 Enfold 홈 첫 화면·메뉴·About Us 전체와 JW 기업개요 #4 전체·메뉴를 비교했습니다. JW 메뉴·#4 첫 화면은 다크 전환도 확인했습니다. 모바일 모든 91개 목적지를 다시 본 것은 아닙니다.

독립 디자인 검토 A: `enfold_content_visual`. 검출기·시각 증거 B: `enfold_elements_visual`. 현재 JW 구현 감사: `current_theme_audit`. A와 B는 서로 결과를 전달하지 않고 조사했습니다. 본문 판단은 직접 시야 관찰과 코드 근거를 합친 정성 평가이며 시장 선호도 조사나 사용자 실험 결과가 아닙니다.

Impeccable는 수동 보조 검사로 사용했습니다. 기업개요 PHP 디렉터리에 `impeccable detect --json`을 실행한 결과는 exit 0, `[]`였습니다. **규칙 감지 0건이 디자인 완성 또는 브라우저 검증 통과를 뜻하지 않습니다.** 사진·내용의 반복, 파사드로 끊기는 흐름, 한글 줄바꿈은 실제 화면과 소스 대조로 확인했습니다. 자동 hook이나 새 디자인 도구를 도입하지 않았습니다.

현재 데모에는 `8.0 MODERN` 표시가 있습니다. 이번 보고서는 2017년 당시의 보존 화면을 평가한 것이 아니라 **오늘 열리는 해당 데모**를 평가합니다. 테마의 오래된 출발 시점과 현재 페이지의 정확한 업데이트 시점을 동일시하지 않습니다.

## Enfold에서 특히 가져올 설계 원리

### 1. 같은 목적에도 다른 읽기 방식을 제공

[Blog의 변형](https://kriesi.at/themes/enfold-2017/blog/)은 카드 색만 바꾸지 않습니다. 큰 대표 기사, 작은 썸네일의 세로 목록, 저자 표시, 전체폭, masonry, 3열 요약은 사용 목적이 다릅니다. [Portfolio](https://kriesi.at/themes/enfold-2017/portfolio/) 역시 작업을 먼저 보여줄지, 설명을 함께 읽힐지에 따라 구성과 여백이 달라집니다.

JW도 일반페이지 5종의 이름을 숫자로만 정의하지 말고 `정보 요약형 / 현장 중심형 / 사람 중심형 / 사례 중심형 / 철학·기록형`처럼 읽기 목적부터 정해야 합니다. 이는 새 상품 범위가 아니라 이미 정한 여러 패턴을 만드는 구체적인 방법입니다.

### 2. 섹션 단위의 변형과 완성 페이지를 함께 제공

[Elements](https://kriesi.at/themes/enfold-2017/elements/)의 가치는 개별 기능의 이름보다 **눈으로 비교 가능한 사용 예제**입니다. 아이콘을 가운데·왼쪽·큰 원형에 두었을 때, 이미지를 전폭·반폭·목업 안에 넣었을 때 어떻게 달라지는지 바로 볼 수 있습니다.

JW가 제공할 최소 단위는 `완성 페이지 → 사용한 섹션 이름 → 섹션 미리보기 → 복사 예제 → 필수 자산·수정 위치`입니다. 관리자 페이지 빌더를 추가할 필요는 없습니다. 고객이 PHP에서 복사해 사용하는 기존 방향에 맞게 섹션 입력값, 독립된 ID, CSS·JS 의존성을 문서화하면 됩니다. 실제 두 테마에서 쓰이기 전에는 저장소 전체 공통 패키지로 성급히 일반화하지 않습니다.

### 3. 효과를 만들기 전에 그 효과가 보여줄 자료 준비

사진 재사용 자체가 결함은 아닙니다. Enfold도 같은 작품 사진을 여러 목록에 사용합니다. 핵심은 같은 자료라도 이미지 우선·설명 우선·크롭·비율·캡션으로 쓰임을 달리하는 것입니다. JW의 부족함은 적은 사진 수와 함께 소개 내용·사진의 역할까지 비슷하게 반복된다는 데 있습니다.

동일한 캠퍼스 사진 3장으로 슬라이더를 만들면 기능은 달라도 새로운 내용은 생기지 않습니다. 슬라이드마다 기업의 공간·사람·결과물 등 다른 근거를 보여줘야 합니다. 패럴랙스도 의미 있는 전경·배경과 크롭이 있어야 하며, 단순 장식 효과의 추가는 우선순위가 낮습니다.

### 4. 흰 공간의 양보다 배치의 관계를 설계

Enfold는 큰 섹션 사이에 짧은 정보 구간을 두고, 같은 열 폭을 계속 반복하지 않습니다. JW는 큰 제목 아래 짧은 문장을 넓게 비워 놓는 패턴에서 벗어나, 필요에 따라 사진 설명·기업표·연혁·프로젝트 메타·인용문을 배치할 수 있습니다. 전단지처럼 내용을 쌓으라는 뜻이 아닙니다. 한 섹션이 맡는 메시지는 줄이고, 메시지에 맞는 자료를 붙이는 방식입니다.

## 기업개요 5종의 현재 평가와 수정 방향

| 페이지 | 유지할 점 | 부족한 점 | 다음 수정 방향 |
| --- | --- | --- | --- |
| #1 | 가장 익숙한 기업소개 흐름, 본문 가독성 | 범용 문장·사진 교차만으로 기업 고유성이 약함 | 핵심 사업·실제 기업 정보·사례 근거가 있는 표준 소개형 |
| #2 | 슬라이더와 기업 정보표의 조합 | 동일 사진 재생이라 소개의 폭이 좁음 | 사진별 역할·캡션을 분리하고 정보표·과정을 중심으로 한 자료형 |
| #3 | 전면 사진과 중간 전폭 구간 | 캠퍼스 사진 재사용, 현장 맥락 부족 | 외관·공간·현장 디테일처럼 연속된 사진 서사가 있는 현장형 |
| #4 | 비대칭 모자이크·사업 행·아코디언으로 형태 변화가 가장 잘 보임 | 예시 사례의 근거와 사진 레퍼토리가 좁음 | 프로젝트 결과물·문제·해결의 연결이 보이는 사례형 |
| #5 | 고정 목차와 긴 본문으로 읽기 방식이 다름 | 반복되는 추상 철학이 길어짐 | 연혁·대표 인용·원칙의 실제 예시가 있는 기록형 |

**현재 5종 중 #4가 형태의 변화는 가장 분명하지만, 이것을 전체 테마의 완성도 충족으로 판단하지 않습니다.** 다섯 개를 모두 #4처럼 바꾸는 것도 해결책이 아닙니다. 각 페이지의 목적을 다르게 유지해야 합니다.

## Enfold에서도 걸러야 할 점

- 옅은 회색 본문과 작은 보조 글씨는 그대로 채택하지 않습니다. JW의 한글 가독성과 라이트·다크 기준을 유지합니다.
- 47개 요소를 한 번에 펼치는 메뉴는 테마 구매자 탐색에는 도움이 되지만 일반 기업 방문자의 메뉴로 적합하다고 단정할 수 없습니다.
- 오래된 스톡 사진·아이콘 분위기, 긴 기능 나열, 카운트다운 등의 장식은 필요한 맥락에서만 씁니다.
- 데모 안의 Ajax 영역·외부 임베드 등 일부는 검토 환경에서 빈 상태 또는 오류를 보였습니다. 풍부한 레이아웃과 모든 기능의 무결성을 혼동하지 않습니다. 상세 상태는 각 시야 기록에 남깁니다.
- 페이지 빌더·뉴스레터·쇼핑·각종 외부 연동까지 JW에 복제하지 않습니다. 이는 기존의 “테마와 매뉴얼에 집중하고 CS 범위를 제한한다”는 방침에 맞지 않습니다.
- Enfold의 이미지·소스·문구를 상품에 가져오지 않습니다. 참조 대상은 구성 원리이며, JW용 자산은 별도 제작·권리 확인이 필요합니다.

## 권장 작업 순서 — 이번에는 실행하지 않음

1. **기존 약속의 실제 동작부터 정리:** FAQ의 실제 jQuery 오류와 구형 UI, 나머지 G5 경로의 잔여 의존성을 처리합니다. 새 페이지 수를 늘리는 일과 분리해 완료 기준을 둡니다.
2. **대표 페이지의 내용과 사진 구성표 확정:** 각 페이지가 어떤 회사를 어떤 근거로 소개할지 정하고, 필요한 인물·공간·결과물·자료 이미지를 배치에 맞춰 준비합니다.
3. **기업개요 5종을 기준 작품으로 다듬기:** 현재 배치 차이는 유지하면서 사진 반복, 추상 문장 반복, 제목 크기와 한글 줄바꿈을 보완합니다. PC·모바일·라이트·다크에서 다시 봅니다.
4. **검증된 섹션을 복사 가능한 단위로 정리:** 새 프레임워크보다 기존 PHP·CSS·JS 안에서 독립 ID·입력값·필수 자산·예제를 먼저 정리합니다. 매뉴얼의 미리보기와 수정 위치를 연결합니다.
5. **방문 경로 단위로 일반페이지 완성:** 회사소개에서 사업 소개·사례·연락처로 이어지는 실제 본문을 완성한 후 다른 변형으로 확장합니다. 75개 출시 범위 자체를 이 보고서에서 변경하지 않습니다.
6. **기능 시험 데이터와 판매 데모 자료 분리:** 페이징 시험용 301개 글은 유지할 수 있지만, 판매 화면의 첫 페이지는 주제·사진·제목 길이가 다양한 검토된 예제로 구성합니다.
