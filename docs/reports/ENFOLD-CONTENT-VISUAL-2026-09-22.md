# Enfold 콘텐츠 화면 실사 — Portfolio·Blog·Shop

작성일: 2026-09-22  
담당 범위: Enfold 2017 데모의 Portfolio·Blog·Shop 메뉴 전체와 Cart, JW-Business 갤러리 비교  
성격: 실제 브라우저 시야 평가 A. 자동 디자인 검출기 결과를 보지 않고 판단했습니다.

## 결론

Enfold의 장점은 기능의 개수나 장식 효과보다 **같은 콘텐츠를 서로 다른 목적에 맞게 배치하는 능력**입니다. 같은 프로젝트 사진과 헤더를 재사용하면서도 열 수, 전체 폭, 이미지 비율, 캡션 유무, 사이드바, 상세 페이지의 설명 위치를 바꿉니다. 이 차이가 구매자가 선택할 수 있는 실제 페이지 패턴이 됩니다.

현재 실제로 확인한 JW-Business 갤러리는 페이지 이동·분류·게시물 정보 등 게시판 기능을 보여주지만, 단색 플레이스홀더 이미지와 반복되는 제목 때문에 완성된 기업 프로젝트 페이지로 보이기 어렵습니다. 우선순위는 효과 추가보다 **콘텐츠에 맞는 사진, 서로 다른 목록 구성, 목록과 이어지는 상세 페이지의 완성**입니다.

Enfold도 무조건 모범 답안은 아닙니다. 작은 회색 글씨, 매우 긴 블로그, 비어 보이는 미디어 영역, Ajax 상세가 채워지지 않는 상태가 관찰됐습니다. 참고 대상은 구성 원리이며, 모든 화면과 기능의 복제가 아닙니다.

## 관찰 방법과 증거 경계

- 브라우저: Microsoft Edge. 데스크톱 CSS 뷰포트 1440×1000.
- 실제 `#avia-menu` 링크를 확인하고 상위 메뉴에 마우스를 올린 후 해당 링크를 클릭했습니다.
- 각 URL에서 마우스 휠로 화면을 내려 중간과 하단을 확인한 뒤 전체 페이지 캡처를 눈으로 검토했습니다. 지연 로딩·등장 효과로 비어 있던 이미지는 다시 스크롤하거나 안정된 후 재확인했습니다.
- 중복 URL도 서로 다른 메뉴 링크이면 각각 클릭했습니다. 총 **28개 메뉴 대상, 중복 제외 26개 URL**입니다.
- 이 문서의 스크린샷 증거는 CUA 도구 대화 출력에 있습니다. 별도 이미지 파일로 저장하지 않았으므로 존재하지 않는 캡처 경로를 제시하지 않습니다.
- 고정 헤더가 긴 전체 페이지 캡처의 중간에 나타나는 현상은 캡처 시점의 스크롤 위치 때문입니다. 웹사이트의 실제 중간 헤더로 판단하지 않았습니다.
- 표에 적힌 높이는 이미지 로딩 이후 관찰한 대략적인 값입니다. 화면 길이 비교용이며 레이아웃의 계약값이 아닙니다.
- URL에 `enfold-2017`이 포함되어도 현재 제공되는 데모입니다. **2017년 당시 원본 화면 또는 당시 지원 기능을 입증하는 자료가 아닙니다.**
- 모바일 검증은 통합 보고서 담당자가 별도로 수행합니다. 이 하위 보고서는 데스크톱 관찰만 주장합니다.
- 장바구니 추가, 주문, 결제, 뉴스레터·문의 양식 제출은 하지 않았습니다.

## 독립 시야 평가 A

### 배울 점

1. **패턴은 장식보다 정보 배치의 차이입니다.** 4열 전폭, 3열 제한 폭, 높이가 다른 갤러리, 사이드바 포함 목록, 히어로 없는 목록은 같은 자료라도 선택 이유가 분명합니다.
2. **한 페이지에서 같은 블록 규칙만 반복하지 않습니다.** Modern Single Entry의 2→1→3→2 이미지 묶음과 Custom Product의 사진·설명 반분 교대가 긴 화면에 리듬을 줍니다.
3. **사진이 실제 레이아웃의 재료입니다.** 맥북·태블릿·화분·안경 등 비교적 일관된 물건 사진을 여러 비율로 보여줍니다. 사진을 단색 카드와 바꾸면 같은 CSS로도 품질이 크게 떨어집니다.
4. **공통 요소가 전체를 묶습니다.** 제목·본문·경로·필터·캡션·푸터가 같은 언어를 유지합니다. 레이아웃 다양성이 무질서한 컬러·버튼 변경으로 이어지지 않습니다.
5. **관련 화면을 옆에서 비교할 수 있습니다.** 사이드바에 변형의 이름을 제공하므로 구매자가 패턴을 발견하고 비교하기 쉽습니다. 고객용 페이지 목록·온라인 매뉴얼에도 유효합니다.
6. **목록과 상세를 함께 설계합니다.** 이미지 중심의 목록 다음에 프로젝트 설명, 고객·업무 정보, 관련 사례를 이어 붙일 수 있습니다.

### 그대로 가져오지 않을 점

1. 본문·메뉴에 작고 옅은 회색 글씨가 많습니다. 현재 화면의 조형 인상을 참고하되 한국어 본문의 읽기 크기와 대비를 더 확보해야 합니다. 정량 접근성 검사를 수행했다는 뜻은 아닙니다.
2. 긴 블로그는 5천~7천px에 이릅니다. 데모의 다양한 형식 전시를 실제 기업 페이지의 적정 길이로 오해하면 안 됩니다.
3. 타임라인, 캡션의 작은 삼각 장식, 조밀한 메타 표기 등은 현대적 표현으로 다시 판단해야 합니다.
4. Ajax 상세가 비어 보인 상태, 일부 미디어가 비어 보인 상태는 참조 전에 별도 동작 확인이 필요합니다.
5. WordPress 페이지 빌더·쇼핑 기능을 동일하게 도입해야 같은 품질이 나는 것은 아닙니다. JW의 PHP 페이지와 복사 가능한 섹션 구조에서도 구성 원리는 구현할 수 있습니다.

## 적용 방향과 우선순위 제안

### 먼저 할 일

- 대표 프로젝트 사진과 사실관계가 이어지는 설명을 준비하고 플레이스홀더를 교체합니다. 산업·공간·서비스 등 테마 시연 업종을 정한 뒤 콘텐츠를 일관되게 구성합니다.
- 기존의 3열 갤러리를 완성한 다음, **이미지 중심 비대칭 목록**과 **설명 중심 2열 또는 사이드바 목록**처럼 사용 목적이 다른 변형을 우선 검토합니다. 같은 카드의 색만 바꾼 변형은 별개 패턴으로 세지 않습니다.
- 프로젝트 상세는 최소한 `큰 시각 자료 → 요약·결과 → 여러 비율의 이미지 → 관련 사례`와 `대표 이미지/핵심 정보 좌우 분할 → 상세 설명`처럼 실제 흐름이 다른 안을 비교합니다.
- 게시판의 필수 조작·권한·페이지 이동은 유지하되 방문자에게 보이는 메타의 위치와 강조 수준은 용도별로 조정합니다.

### 공통 관리 방식

- 이미지 비율, 콘텐츠 최대 폭, 섹션 간격, 제목·본문·캡션, 필터·페이지 이동·관련 사례의 디자인 계약은 공통으로 유지합니다.
- 페이지 변형은 열 수만이 아니라 `이미지 우선 / 설명 우선`, `넓은 전시 / 좁은 읽기`, `목록 탐색 / 개별 사례 설명`으로 구분합니다.
- 고객이 섹션을 복사해 쓸 때 필요한 코드·에셋·스크립트 의존성과 권장 이미지 비율을 온라인 매뉴얼에 함께 표시합니다.
- 공통화는 실제 두 개 이상에서 반복되는 구조를 확인한 뒤 수행합니다. 페이지 빌더나 새로운 설정 시스템을 이 조사만으로 추가하지 않습니다.

### 이번 조사로 확정하지 않은 것

- 새로운 상품 기능·판매 범위·추가 페이지 수의 확정
- 고객 사이트에 대한 쇼핑 기능, Ajax 프로젝트 로더 또는 뉴스레터 도입
- Enfold의 접근성·성능·보안 적합성
- 다른 데모 전체, 모바일 모든 상태, 장바구니·결제 흐름
- JW 수정·배포. 이번 작업은 조사와 보고서 작성만 수행했습니다.
