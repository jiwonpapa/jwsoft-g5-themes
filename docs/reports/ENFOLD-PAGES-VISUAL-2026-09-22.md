# Enfold — Home·Features·Pages 직접 시야 검토

검토일: 2026-09-22. Edge, PC 1440×1000. 대상은 [Enfold 2017 데모](https://kriesi.at/themes/enfold-2017/)의 현재 공개 화면입니다. 제품 코드 수정·설치·폼 전송은 하지 않았습니다.

## 검토 방법과 경계

상단 메뉴와 메가메뉴를 실제로 펼쳐 각 링크를 클릭했습니다. 각 고유 페이지는 화면 단위로 스크롤하여 하단 도달을 확인하고 스크린샷을 직접 읽었습니다. 전체 페이지 캡처만으로 판단하지 않고, 홈의 주요 구간과 움직이는 화면은 뷰포트 캡처도 확인했습니다. 스크린샷은 작업 도구 기록에 있으며 별도 PNG 파일을 저장하지 않았습니다.

메뉴의 중복 목적지는 별도 페이지로 세지 않았습니다. Pages의 슬라이더 5개는 여기서도 메뉴 클릭을 했으나 전체 내용 분석은 Elements 조사와 합칩니다. 모든 내부 버튼·모든 슬라이드·모든 블로그 글·전 세계 Enfold 데모를 전수 시험한 것은 아닙니다.

현재 홈과 Layerslider에 `ENFOLD 8.0 MODERN`이 표시됩니다. URL에 2017이 있다고 현재 사이트 전체를 2017년 출시 당시 그대로라고 단정할 수 없습니다. 이 차이가 오래된 테마 계열에서도 풍부한 구성이 보인다는 관찰을 무효화하지는 않습니다. 판매량·지원 기간 문구 역시 데모 문구이며 이번에 계약이나 현재 판매 수치를 검증한 것은 아닙니다.

## 화면을 통해 확인한 설계 원리

### 1. 섹션 수보다 서로 다른 정보 표현

팀 소개는 사진·소개를 바둑판처럼 교차시키고, 서비스는 아이콘 탭과 넓은 상세 영역을 씁니다. 가격 페이지는 비교표의 행 정렬과 강조 칼럼으로 선택을 돕습니다. FAQ는 질문을 접고 펼치며, Help는 같은 지원 목적도 자료 디렉터리로 구성합니다. 제목과 사진을 바꾼 동일 템플릿이 아닙니다.

### 2. 하나의 이미지가 맡는 역할도 다양함

홈의 사진 배경, 경계를 넘어가는 대형 기기 목업, 주석을 붙인 화면 합성, 대각선 페이지 콜라주, 팀의 인물 사진, 배경이 제거된 단체 사진은 서로 다른 일을 합니다. 목업은 제품을 설명하고 인물은 조직을 보여줍니다. JW의 캠퍼스·협업·회의실 사진 3개만 크기와 위치를 바꾸는 방식보다 표현의 범위가 넓습니다.

### 3. 여백과 정보량을 함께 다룸

모든 구간을 크게 비우지도, 매번 카드를 촘촘하게 채우지도 않습니다. 큰 사진·넓은 선언문 다음에는 작은 정보 목록이나 표를 놓습니다. 홈은 길지만 큰 덩어리, 낮은 정보 띠, 교차 구성으로 속도가 달라집니다. 다만 기능 판매용 홈의 전체 길이를 보통 기업 사이트에 그대로 적용할 필요는 없습니다.

### 4. 반복은 공통 기준에서, 변화는 본문에서

헤더, 경로 표시, 얇은 선, 본문 폭, 버튼, 푸터는 반복됩니다. 다른 것은 섹션 안의 비율·사진 종류·정보 구조입니다. JW 역시 공통 색·버튼·글꼴을 유지하면서 회사소개 5종의 내부 구성은 다르게 만드는 방향이 맞습니다.

## 직접 확인한 동작

- 상단 Pages 메가메뉴 펼침과 하위 전체 목적지 이동.
- Home과 Landing/Front Page가 같은 홈을 가리킴.
- 스크롤에 따라 투명 헤더가 흰색 고정 헤더로 바뀌는 화면.
- FAQ 첫 질문 클릭 후 답변이 펼쳐지는 상태.
- 검색 아이콘 클릭 후 헤더 아래 작은 검색 입력 패널이 열림.
- Coming Soon 카운트다운은 이번 관찰 시 모두 0. 운영 중 카운트다운 정상 작동을 증명하지 않음.
- Maintenance 진행 막대는 화면의 예시 표현. 서버 점검 관리 기능을 검증한 것이 아님.

슬라이더의 진입 fade 때문에 첫 캡처에서 글자·사진이 희미할 수 있습니다. 안정된 상태를 다시 확인했으며, 전체 페이지 캡처에서 고정 헤더가 중간에 끼는 현상은 캡처 방식의 한계로 제품 결함에 포함하지 않았습니다.

## 그대로 가져오지 않을 부분

옅은 회색 본문, 오래된 아이콘·스톡 사진 분위기, 긴 기능 나열, 거대한 요소 메가메뉴는 현대화 대상입니다. 뉴스레터·쇼핑·페이지 빌더의 존재를 JW에 같은 기능을 추가해야 한다는 근거로 삼지 않습니다. 필요한 것은 테마 범위 안의 **완성된 페이지와 복사 가능한 시각 섹션 예제**입니다.

## 모바일 대표 화면 추가 확인

같은 Edge의 CSS 뷰포트를 390×844로 변경하고 실제 너비를 확인했습니다. 모바일 실기기 시험은 아닙니다.

- Enfold 홈 첫 화면: PC의 사진 히어로가 낮은 가로 이미지로 바뀌며, 이미지 안의 큰 로고 문구도 함께 작아집니다. 아래 3열 장점은 세로로 쌓입니다.
- 메뉴 열기: 안정된 상태에서 화면 전체를 덮는 메뉴가 나타납니다. Portfolio·Blog·Pages·Elements의 하위 항목을 긴 세로 목록으로 모두 펼칩니다. 메뉴 안에서 스크롤해 Pages 아래 About Us를 눌렀습니다. 여러 대분류를 이동할 때 많은 스크롤이 필요합니다.
- About Us: 하단까지 직접 스크롤했습니다. 2열 설명·인물 사진·수치·후기는 세로로 바뀝니다. 약 8,070px까지 길어졌고 별도 가로 넘침은 관찰되지 않았습니다. 인물 갤러리는 첫 통과 시 어두운 빈 구간처럼 보였으나 다시 위로 스크롤했을 때 정상 사진이 표시돼 영구 누락으로 판정하지 않았습니다.
- JW 기업개요 #4: 같은 폭에서 처음부터 약 4,099px 하단까지 확인했습니다. 모자이크 일부 배치는 유지되고 사업 목록·아코디언·문의가 세로로 이어집니다. 한글 본문 대비는 Enfold보다 명확하게 느껴졌습니다. 이는 정량 대비 검사 결과가 아닙니다.
- JW 메뉴: 왼쪽 대분류를 고정한 채 오른쪽 하위 내용만 바뀝니다. 회사소개→사업분야 이동을 눌러 확인했습니다. Enfold의 긴 전체 하위 목록보다 대분류 전환이 간결합니다. 메뉴의 라이트·다크 전환과 #4의 다크 첫 화면도 확인했습니다.

JW는 기존 관리자 로그인 상태였습니다. 모바일 모든 페이지·모든 다크 구간을 새로 검증한 것은 아닙니다. 검토 후 라이트 설정과 임시 뷰포트 설정을 원복했습니다.
