# JW-Business 현재 구현 재고 — Enfold 비교용

작성일: 2026-09-22. 대상: `themes/business/jw_business`의 현재 원본 코드.

이 문서는 **코드 감사와 실제 개발 사이트 시야 검증**을 분리해 기록합니다. 1~5절은 코드 관찰이며, 후속 요청으로 수행한 새 브라우저 검증은 6절입니다. Enfold의 실제 화면 관찰은 별도 비교 보고서가 담당합니다. 제품 소스 수정·빌드·배포는 수행하지 않았습니다.

## 핵심 판단

현재 JW-Business는 **공통 UI와 일부 G5 기능, 실제 메인 1개, 기업개요 5개를 구현한 개발 중 테마**입니다. 75개 URL을 연결했으나 75개 디자인을 만든 상태가 아닙니다. 기업개요의 배치 차이는 코드상 분명하지만, 사진·메시지·섹션 자산이 좁아 완성된 대형 테마의 페이지 폭과 동등하다고 평가할 근거는 없습니다.

## 4. G5 고유 기능은 부분 현대화 상태입니다

- `basic` 게시판 목록·본문·댓글·쓰기와 `gallery` 목록은 새 UI입니다. 갤러리 본문·댓글·쓰기는 basic을 재사용하고 모바일은 PC 원본을 include합니다.
- 계획의 게시판 6표현형 중 현재 독립 디렉터리는 `basic`, `gallery`뿐입니다. `portfolio`, `webzine`, `download`, `video` 완성을 주장할 근거가 없습니다.
- 새로운 최신글 `home_news`가 있으나 기본 `basic`, `notice`, `pic_basic`, `pic_block`, `pic_list` 5개 PHP는 반입 원본 SHA-256과 동일합니다. 최신글 8표현형 완성 상태가 아닙니다.
- FAQ PHP 1개, 1:1 문의 PHP 5개도 반입 원본과 hash가 동일합니다. FAQ는 기본 CSS·Font Awesome, QA는 기본 CSS·jQuery 호출을 유지합니다. 공개 head는 jQuery를 포함하지 않아 실제 경로에서 기능 오류가 생길 수 있으므로 시야·조작 검증 대상으로 남습니다. 이번 코드 감사만으로 현재 런타임 실패를 단정하지 않습니다.
- 회원 원본 PHP 20개 중 12개가 원본 hash와 같습니다. 여기에는 폼메일·쪽지·포인트·프로필·스크랩 등 사용자 화면뿐 아니라 UI가 없는 연동 파일도 있으므로 **12개 미완성 화면**이라고 단순 집계하면 안 됩니다.
- `src/php/**/*.php` 검색에서 `itemscope`, `itemtype`, `itemprop`, `application/ld+json` 출력은 찾지 못했습니다. 일반페이지 메타 계약은 구현되었지만 계획한 게시판 구조화 데이터 구현 완료 증거는 없습니다.

근거: `skin/board/gallery/view.skin.php:3`, `mobile/skin/board/gallery/list.skin.php:3`, `skin/latest/home_news/latest.skin.php`, `skin/faq/basic/list.skin.php:5`, `skin/qa/basic/list.skin.php:10` 및 `61`, `docs/BASIC-INVENTORY.json`과 현 파일 SHA-256 비교. `scripts/build-payload.ts:93`~`105`는 영카트와 screenshot을 제외하고 source를 복사하므로 이 파일들은 단순 참고용 원본이라는 이유만으로 배포 대상에서 빠지지 않습니다.

기존 기능 보고서의 미검증 범위도 유지해야 합니다: 실제 신규 CAPTCHA 가입 성공, 외부 본인확인·메일·소셜, 실제 첨부 업로드, 선택 이동/복사 전체 동작, 판매 ZIP 설치·업데이트·롤백은 완료로 보고되어 있지 않습니다(`docs/reports/JW-BUSINESS-COMMUNITY-REVIEW-2026-09-21.md`).

## 5. 재사용 구조와 구매자 편집성

코어를 수정하지 않고 얇은 `/pages/*.php` 진입 파일이 활성 테마 renderer를 부르며, `custom/site.php`와 `custom/navigation.php`로 설정을 덮어쓰는 구조는 있습니다. Bun/Vite가 배포 자산을 만들기 때문에 고객 서버 빌드가 필요 없는 방향도 맞습니다.

그러나 현재 기업개요는 **페이지별 큰 PHP 본문 5개**입니다. 공통 사진 helper와 CSS를 공유하되 독립 section partial·입력 계약·section manifest·페이지 recipe로 분해된 구현은 확인되지 않습니다. `catalog.json`의 `sections`는 구현 예정 이름 배열이며 실제 renderer 조립 데이터가 아닙니다. 홈페이지도 하나의 PHP 안에 섹션이 연속됩니다.

따라서 지금을 구매자용 섹션 라이브러리 완성이라고 안내하면 안 됩니다. 구매자가 섹션을 이동하려면 관련 CSS/JS뿐 아니라 `$jw_photo`, `$jw_link`, `$jw_company_name` 같은 상위 문맥과 `company-*` anchor ID도 이해해야 합니다. 같은 섹션을 두 번 붙이면 중복 ID가 생길 여지도 있습니다. 별도 페이지 빌더를 만들 필요 없이, 승인된 섹션부터 입력값·고유 ID·필수 자산을 명시한 복사 예제로 제공하면 됩니다.

근거: `pages/company-overview.php:16`~`24`, `pages/company-overview/5.php:5`~`11`, `lib/jw-business.lib.php:40`~`43` 및 `135`~`141`, `scripts/build-payload.ts:70`.

## 비교 리포트에 반영할 결론

1. 최신 라이브러리·다크 모드·검사 도구는 기반의 장점이지 **시각 완성도 우위의 증거**가 아닙니다.
2. Enfold와 비교할 때 우선 볼 것은 메뉴 목적별 완결된 본문, 사진 선택의 폭, 서로 다른 섹션의 조합, CTA 이후의 완성도입니다.
3. 현재 JW는 기업개요 5종의 레이아웃 차이를 확보했으나 자료·콘텐츠·도착 페이지가 충분하지 않습니다. “구형 디자인보다 현대적이므로 우수하다”는 판단은 부적절합니다.
4. 다음 작업을 승인받으면, 75개 숫자 확대보다 대표 페이지와 연결되는 실제 본문·잔여 G5 기능을 완결하고 그 결과를 섹션 재사용 계약으로 정리해야 합니다. 이번 요청에서는 분석만 수행합니다.

### 실제 확인한 FAQ 오류

FAQ 로딩 후 브라우저 콘솔에서 다음 두 오류를 확인했습니다. 앞의 코드 감사에서 가능성으로 남겼던 jQuery 의존 문제 중 **FAQ의 로딩 오류는 런타임에서도 확인**한 것입니다.

```text
ReferenceError: jQuery is not defined
  https://g5themes.test/js/viewimageresize.js:102:3
ReferenceError: jQuery is not defined
  https://g5themes.test/bbs/faq.php:522:1
```

등록 항목이 없어 FAQ 답변 펼침의 실패 여부까지 시험할 수는 없었습니다. 이번 요청은 비교 분석이므로 소스를 수정하거나 데이터를 채우지 않았습니다.

### 메뉴와 데모 표현

고객지원 메가 메뉴는 앞의 두 열에 `#1 FAQ·공지·문의 요약`, `#2 문의 목적별 안내` 등 변형 선택을, 나머지 열에는 공지·FAQ·1:1 문의 한 개씩을 배치합니다. 판매 데모의 변형 목록과 실제 기업 방문자의 메뉴가 섞인 상태입니다. 기업개요의 다른 디자인 링크는 하단의 작은 `#1`~`#5`뿐이어서 사용 목적과 시각 차이를 선택 전에 파악하기 어렵습니다.

이는 75개 경로를 먼저 연결하라는 기존 작업 단계에는 맞지만, 완성된 판매 데모와 비교할 때는 구별해서 평가해야 합니다. 이후 판매 데모에서는 패턴 미리보기와 실제 기업 사이트 메뉴의 역할을 명확히 할 필요가 있습니다. 관리자·페이지 빌더를 새로 만들자는 제안은 아닙니다.

### 화면을 본 후의 우선순위

1. 홈 CTA가 도달하는 사업 소개, 메뉴에 노출한 일반페이지와 FAQ를 실제 본문·기능으로 완결합니다.
2. 갤러리와 기업개요에 목적이 구분되는 사진·프로젝트·인물·실제 길이의 예시 자료를 준비합니다. 현재 자료를 늘려 복제하는 방식은 피합니다.
3. 제목만 크게 하고 짧은 설명을 넓은 공백에 놓는 리듬을 줄이고, 구체 정보가 필요한 위치에 표·사례·시각 자료를 배치합니다. 모든 페이지를 빽빽하게 채우자는 뜻은 아닙니다.
4. 한글 줄바꿈과 제목/본문 비율을 실제 폭에서 다시 조정하고, 그 규칙을 공통 스타일로 정리합니다.

이번 새 브라우저 확인은 PC 라이트에 한정했습니다. 모바일·다크·비회원·실제 폼 저장은 이번에 재검증하지 않았습니다. 스크린샷은 도구 결과에서 직접 검토했으며 별도 이미지 파일로 저장하지 않았습니다.
