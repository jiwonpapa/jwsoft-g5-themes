# JW-Business 전체 메뉴 디자인 재점검

2026-09-23 · 범위: `g5themes.test` 개발 화면 · 판정: **현재 디자인으로 판매 불가**

## 결론

Avada·Enfold·Apple 제품 페이지 연구가 일부 화면의 구성과 효과로 옮겨진 흔적은 있다. 그러나 연구의 핵심인 목적별 시각 자료, 장면 전환, 페이지마다 다른 설득 흐름이 테마 전체에 적용되지 않았다. 일반 페이지 70종 중 54종은 같은 안내 스캐폴드이고, 본문이 작성된 16종도 사진 원본 세 장과 흰색/연회색의 제목·목록·문의 구간에 지나치게 의존한다. **서로 다른 PHP 파일과 섹션 순서는 존재하지만, 구매자가 구별할 만한 70개 완성 디자인이나 판매용 데모는 아니다.**

이 판정은 디자인에 대한 것이다. 더미 연락처·가상 사례 사용이나 실제 문의 처리 여부를 결격 사유로 계산하지 않았다. 기존 문서의 `구현·반영 완료`는 화면이 존재한다는 기록일 뿐 시각 품질 승인이 아니다.

## 확인한 범위와 한계

- Codex 내장 브라우저에서 메뉴의 일반 페이지 **70개 URL을 모두 직접 열었다**. 작성본 16종은 첫 화면과 중간을 모두 봤고, 각 묶음의 대표 페이지는 마지막 문의 구간까지 봤다. 미작성본 54종은 각 URL의 실제 안내 스캐폴드를 확인했다.
- 메인 선택형 #2~#5는 첫 화면·중간, 원페이지 제품형·서비스형·프로젝트형은 첫 화면·중간·끝을 봤다. 앞선 메인 #1 직접 시야 평가도 종합 판단에 포함했다.
- 프로젝트·게시판·고객지원 하위의 갤러리, 자유게시판, 공지, 포트폴리오, 뉴스룸, 자료실, 영상자료, 최신글 모음, FAQ, 1:1 문의 진입 화면을 열었다. 1:1 문의는 비회원에서 로그인으로 이동했다.
- 모바일 390×844에서 기업개요 #3, 사업소개 #5, 디지털 상세 #2, 인사말 #1의 상단·중간을 비교했다. 라이트/다크와 모든 70종의 모바일 전체 길이를 전수 검수했다는 뜻은 아니다. 이번 점검은 판매 ZIP·설치·기능 QA가 아니다.
- 로컬 `bun run quality:check`를 읽기 전용으로 실행했으며 **실패**했다. 개발 사이트의 배포본과 작업 중인 로컬 소스의 바이트 단위 동일성은 확인하지 않았다. 다만 아래의 주요 사진과 스캐폴드 문제는 브라우저와 로컬 소스 양쪽에서 확인했다.

일반 페이지 집계: 기업개요 5 + 사업소개 5 + 사업상세 5 + 문의 1 = **작성 16**. 나머지 **54**는 브라우저에서 동일한 `공통 renderer를 호출하지 않는 독립 PHP 페이지입니다` 및 `이 파일 안에서 완성할 독립 섹션` 안내를 보였다.

## 반복·사진의 직접 증거

1. 현재 로컬 품질 검사는 `home-collaboration.webp`를 **13개 페이지**, `home-project.webp`를 **11개**, `home-hero.webp`를 **8개**에서 사용한 것으로 보고하며 `PHOTO_REUSE`·`PHOTO_OWNER`로 실패한다. 이 세 원본이 기업개요, 사업소개, 사업상세와 일부 메인에 걸쳐 있다. 사진의 파일명만 다른 문제가 아니라 실제 브라우저에서 같은 건물·회의실·두 사람의 협업 장면이 반복해서 보였다.
2. 일반 페이지 사진의 시각적 역할도 어긋난다. 디지털 서비스 설명에 회의실, 디지털 개선 사례에 같은 회의실을 크게 배치한다. 공간/건축 분야로 기운 사진을 전략·디지털·기업 소개의 공통 대표 이미지로 돌려 쓰면서 업종별 설득력이 떨어진다.
3. 동일한 카드/블록의 순서를 바꾸는 것만이 전부는 아니다. 기업개요 #3의 전폭 사진, #5의 고정 목차, 사업소개 #2의 교차 구성처럼 구조 변화는 있다. 그러나 첫 화면의 제목·보조 문장, 중간의 연회색 정보 구간, 마지막의 문의 띠가 반복되어 **페이지 전체의 인상은 거의 같아진다**. 특히 모바일에서는 구성의 상당수가 단일 열의 제목·문장·사진 순서로 평탄화된다.
4. `quality:check`는 사진·첫 화면 반복뿐 아니라 작성 21종(홈 5 + 일반 16)의 디자인 준비/검토 기록과 디지털 결과 자료 부족으로 실패한다. 검사 실패는 판매 불가 판정의 보조 증거이며, 자동 검사만으로 디자인을 판정한 것은 아니다.

## 연구 적용 성과 판정

| 연구에서 기대한 것 | 현재 보이는 적용 | 판정 |
| --- | --- | --- |
| Enfold: 사진 역할과 크기, 정보 표현, 읽는 동작의 변화 | 기업개요 5종에서 구획·표·전폭 사진·고정 목차로 일부 변형 | **부분 적용**. 같은 원본 사진 세 장과 추상적 문장이 변형의 효과를 무너뜨린다. |
| Avada/Enfold: 서비스→과정→사례→사람/근거→문의의 설득 흐름 | 홈/원페이지에 일부 순서와 앵커, 표, 아코디언 | **미달**. 실제 화면/결과 자료가 부족하고 다수의 일반 페이지는 비어 있으며, 페이지 후반이 반복 문의 구간으로 끝난다. |
| Apple iPhone 제품 페이지: 제품 전용 이미지·스크롤 장면·선택형 설명 | 제품형 원페이지에 전용 렌더와 각도 변화 | **국소적 성과**. 다른 원페이지와 일반 페이지에는 목적별 전용 장면/자산 체계가 확장되지 않았다. Apple과 동급 연출이라고 볼 근거는 없다. |
| 같은 목적의 5종이 서로 다른 선택 이유를 줄 것 | 파일명·메뉴명과 일부 본문 배치는 다름 | **실패**. 54종은 미작성이고, 작성본도 사진·타이포·구간 리듬이 반복된다. |

따라서 이번 결과는 **연구 수행의 기록은 있으나, 연구를 판매 가능한 디자인으로 변환하는 데 실패한 상태**다. 지금 결과를 제작 역량의 최대치로 볼 이유는 없다. 디자인 방향·전용 이미지·목적별 첫/중간/끝 장면을 먼저 확정하고 한 묶음을 시야 비교로 통과시킨 뒤 다른 묶음으로 확장해야 한다. 단순히 효과, 아이콘, 카드 수, 페이지 수를 더하는 것으로는 해결되지 않는다.

## 이번 점검의 변경 범위

테마 소스, 개발 사이트, 서버, 품질 규칙은 변경하지 않았다. 이 보고서만 작성했다.
